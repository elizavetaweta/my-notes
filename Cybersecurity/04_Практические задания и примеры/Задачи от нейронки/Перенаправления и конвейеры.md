### 💡 Советы по улучшению (необязательно, но полезно)

> [!note] Как сделать команду более универсальной и читаемой
> Ниже — несколько приёмов, которые делают команду **информативнее** (видна дата аудита), **надёжнее** (меньше дублирования) и **удобнее** (отсортированный вывод).

| Что улучшить              | Как было                                           | Как можно сделать                                               | Почему так лучше                                               |
| ------------------------- | -------------------------------------------------- | --------------------------------------------------------------- | -------------------------------------------------------------- |
| **Дублирование `find`**   | Два отдельных вызова для `/usr/bin` и `/usr/sbin`  | Один вызов: `find /usr/bin /usr/sbin -type f ...`               | Меньше кода, легче добавить третий каталог или изменить маску. |
| **Сортировка**            | Список не отсортирован                             | Добавить `\| sort` в конвейер                                   | Удобнее читать и сравнивать списки при повторном аудите.       |
| **Отсутствие даты**       | Не видно, когда выполнен аудит                     | Добавить `echo "Аудит от $(date)"` в начало файла               | Повышает ценность отчёта для документирования.                 |
| **Жёсткие пути**          | Только `/usr/bin` и `/usr/sbin`                    | Использовать переменную `$PATH` или несколько стандартных путей | Не пропустит программы в нестандартных местах.                 |
| **SUID и SGID раздельно** | SUID-файлы и SGID-файлы в одном списке без пометок | Перед каждым списком вывести заголовок `echo "=== SUID ==="`    | Сразу видно, какой файл к какой категории относится.           |

**Пример улучшенной команды:**

```bash
{ echo "Аудит SUID/SGID от $(date)"; find /usr/bin /usr/sbin -type f \( -perm -4000 -o -perm -2000 \) -print0 | sort -z | xargs -0 ls -la; } > suid_sgid_audit.txt
```

## 📋 Задание 2. Аудит прав на критические файлы

1. Проверь права доступа к файлам `/etc/shadow`, `/etc/sudoers` и `/etc/ssh/sshd_config`.
2. Сохрани вывод (владелец, группа, права) в файл `critical_permissions.txt`.

**Мои команды:**
```bash
ls -la /etc/shadow /etc/sudoers /etc/ssh/sshd_config
ls -la /etc/shadow /etc/sudoers /etc/ssh/sshd_config | awk '{print $1,$3,$4,$9}' > critical_permissions.txt
```
[[ls ]] и [[awk]]

**Что получилось:**
-rw------- root root /etc/shadow
-rw-r--r-- root root /etc/ssh/sshd_config
-r--r----- root root /etc/sudoers

Как можно улучшить:
Простой вариант, применяя [[stat]] -c

```bash
stat -c '%A%U%G%n' /etc/shadow /etc/sudoers /etc/ssh/sshd_config > critical_permissions.txt
```
Более сложный вариант:

```bash
{ echo "Аудит критических файлов от $(date)"; stat -c '%A %U %G %n' /etc/shadow /etc/sudoers /etc/ssh/sshd_config 2>/dev/null; } > critical_permissions.txt
```

📝 Пояснение улучшений
- { ... } группирует заголовок и вывод stat, чтобы всё попало в один файл.

- stat -c '%A %U %G %n' — выводит ровно то, что нужно: права доступа, владелец, группа, имя файла. Формат не зависит от версии ls и не «плывёт».

- 2>/dev/null — подавляет ошибки, если какого-то файла нет. В реальном аудите ошибки лучше фиксировать отдельно, но для лабораторной так проще.

## 📋 Задание 3. Подсчёт процессов

1. Подсчитай, сколько всего процессов запущено в системе.
2. Подсчитай, сколько из них запущено от имени `root`.
3. Сохрани оба числа в файл `process_count.txt`, сопроводив их текстом: «Total processes: N», «Root processes: M».

**Мои команды:**
```bash
echo -e "Total processes: $(ps aux --no-headers | wc -l)\nRoot processes: $(ps -u root -U root --no-headers | wc -l)">process_count.txt 

```

**Что получилось:**
Total processes: 460
Root processes: 348

✅ Правильные команды

- Общее количество процессов:

```bash
ps aux --no-headers | wc -l
```

--no-headers убирает строку-заголовок, чтобы не считать её.

wc -l считает количество оставшихся строк = количество процессов.

- Количество процессов от root:

```bash
ps -U root -u root --no-headers | wc -l
```

-U root — процессы, у которых реальный пользователь (real user ID) = root.

-u root — процессы, у которых эффективный пользователь = root.

Эта комбинация надёжно отбирает процессы именно root, не захватывая лишнего.


Изначально задумка была иная:

```bash
echo -e "Total processes: $(ps aux | tail -1 | awk '{print $2}')\nRoot processes: $(ps aux | grep -c "root")">process_count.txt
```

Почему это неверно:
1. **`ps aux | tail -1 | awk '{print $2}'`**
    
    - `tail -1` берёт **последнюю строку** вывода `ps`, а это часто сам `tail`, запущенный в фоне.
        
    - `awk '{print $2}'` печатает второй столбец, то есть **PID** этого процесса, а не общее количество процессов. Число `21444` — это просто PID, а не число процессов.
        
2. **`ps aux | grep -c "root"`**
    
    - Эта команда считает строки, в которых встречается слово `root`. Оно может быть не только в столбце `USER`, но и в команде (например, путь `/root/...`), и заодно сам `grep root` тоже попадёт в подсчёт. Поэтому `348` — число с погрешностью.


### 💡 Альтернативный вариант с `awk` (один проход вместо двух `ps`)

> ps aux --no-headers | awk 'BEGIN { total=0; root=0 } { total++; if ($1 == "root") root++ } END { printf "Total processes: %d\nRoot processes: %d\n", total, root }' > process_count.txt

## **Как это работает:**

1. ps aux --no-headers

ps aux — список всех процессов в user-ориентированном формате.

--no-headers — убрать строку-заголовок (USER, PID, %CPU...), чтобы не считать её за процесс.

Вывод передаётся в awk через конвейер |.

2. BEGIN { total = 0; root = 0 }

BEGIN — блок, который выполняется один раз, до обработки строк.

total = 0 — создать переменную-счётчик для всех процессов.

root = 0 — создать переменную-счётчик для процессов root.

Обе стартуют с нуля.

3. { total++; if ($1 == "root") root++ }

Блок без метки — выполняется для каждой строки вывода ps.

total++ — увеличить счётчик всех процессов на 1.

if ($1 == "root") root++ — если первый столбец ($1, имя пользователя) равен root, увеличить счётчик root на 1.

4. END { printf "Total processes: %d\nRoot processes: %d\n", total, root }

END — блок, который выполняется один раз, после обработки всех строк.

printf — форматированный вывод.

Шаблон содержит два спецификатора %d (decimal — целое число) и переносы строк \n.

Первый %d заполняется первым аргументом (total), второй — вторым (root).

Порядок аргументов жёстко привязан к порядку %d в шаблоне: первый %d → первый аргумент, второй %d → второй аргумент.

5. > process_count.txt

Записывает итоговый вывод в файл.

## 💡 Как это работает в целом (аналогия)
Представь робота, который перебирает стопку карточек (строки вывода ps):

Для каждой карточки он ставит галочку в блокноте «Всего» (total++).

Если на карточке написано root, он ставит дополнительную галочку в блокноте «Root» (root++).

Когда карточки закончились, робот пересчитывает галочки в обоих блокнотах и записывает результат.

Вся магия — в том, что total++ выполняется для каждой строки без условий, поэтому считает всё. А root++ — только при выполнении условия $1 == "root".

**Сравнение с твоим вариантом (`echo` + 2 × `wc -l`):**

| Характеристика | Твой вариант | Вариант с `awk` |
|---|---|---|
| **Сколько раз запускается `ps`** | Дважды | Один раз |
| **Читаемость** | Очень простая | Чуть сложнее, но всё ещё читаемая |
| **Гибкость** | Только подсчёт | Можно добавить фильтры и статистику |

Твой вариант — абсолютно правильный. `awk` показывает, как можно сделать то же самое эффективнее, когда данных много.
