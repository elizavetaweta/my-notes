# 📊 ps — список процессов

> [!abstract] Суть одной фразой
> `ps` (Process Status) показывает снимок запущенных процессов в [[Linux]]. Это первый инструмент для выявления подозрительной активности, проверки прав процессов и поиска вредоносного ПО.

---

## 📌 Базовое использование

> ps aux

Показывает **все** процессы от всех пользователей в детальном формате.

- `a` — процессы всех пользователей.
- `u` — user-ориентированный формат (владелец, CPU, память).
- `x` — процессы без терминала (демоны).

---

## 🔑 Полезные комбинации

**Показать процессы конкретного пользователя:**
> ps -u username

**Показать процессы, слушающие порты (древовидно):**
> ps aux --forest

**Найти процесс по имени:**
> ps aux | grep sshd

---

## 🔑 Ключевые опции

- `a` (**a**ll users) — показать процессы всех пользователей, а не только текущего.
- `u` (**u**ser-oriented) — выводить информацию о пользователе, использовании CPU и памяти.
- `x` (no controlling **t**erminal) — показать процессы, не привязанные к терминалу (демоны, фоновые службы).
- `-U` (**r**eal user) — фильтр по реальному пользователю (тому, кто запустил процесс).
- `-u` (**e**ffective user) — фильтр по эффективному пользователю (тому, чьи права используются).
- `--no-headers` — не выводить строку с названиями столбцов. Полезно при передаче в `wc -l` для точного подсчёта.
- `-e` или `-A` (**e**verything) — показать все процессы (аналог комбинации `aux`).
- `-o` (**o**utput) — указать свои столбцы для вывода, например `ps -eo pid,user,%mem,cmd`.
- `-f` (**f**ull) — полный формат вывода с дополнительной информацией.
- `--forest` — показать иерархию процессов в виде дерева.
- `--sort` — сортировка по заданному столбцу (например, `--sort=-%mem` для сортировки по памяти).

> [!tip] Примеры для аудита
> Точный подсчёт процессов root:
> ```bash
> ps -U root -u root --no-headers | wc -l
> ```
> Поиск самого прожорливого процесса:
> ```bash
> ps -eo pid,user,%mem,cmd --sort=-%mem | head -10
> ```

## 📜 Почему `aux` без дефисов

Существует два исторических «диалекта» опций `ps`:

- **POSIX (System V):** строгий стандарт. Все опции начинаются с дефиса (`-u`, `-e`, `-U`).
- **BSD:** более старый и вольный стиль, где опции пишутся без дефисов (`aux`, `U`).

Команда `ps aux` использует сразу три BSD-опции: `a`, `u` и `x`. Linux-версия `ps` умеет понимать и тот, и другой стиль, но **выбирает один из них на основе первой переданной опции**. Как только она видит `aux` (BSD-стиль), она переходит в этот режим и перестаёт корректно воспринимать POSIX-опции с дефисами. Именно поэтому смешивать стили нельзя.


## 👤 Реальный и эффективный пользователь (`-U` vs `-u`)

У каждого процесса есть два идентификатора владельца:

- **Реальный (real user ID)** — кто **на самом деле** запустил процесс (чей «паспорт»).
- **Эффективный (effective user ID)** — от чьего имени процесс действует **прямо сейчас** (чей «пропуск»).

Обычно они совпадают. Исключения:
- **SUID-программы:** меняют эффективного пользователя на владельца файла (например, `passwd` временно работает от root).
- **sudo:** меняет эффективного пользователя на root, оставляя реального прежним.

| Флаг | Значение | Пример вывода для `sudo passwd` |
| :--- | :--- | :--- |
| `-U` (real) | Реальный владелец | `shadowbunny` |
| `-u` (effective) | Эффективные права | `root` |

> [!tip] Для точного подсчёта процессов root
> Комбинация `-U root -u root` отбирает только процессы, которые и запущены, и работают с правами root. Это исключает временно повышенные процессы обычных пользователей.

## 🕵️ Примеры для специалиста по ИБ

**Проверить подозрительный процесс (нестандартный путь, странное имя):**
> ps aux | grep -vE "(systemd|kworker|dbus)"

**Найти процессы, запущенные от root, без терминала:**
> ps -U root -u root u

**Показать процессы, потребляющие больше всего памяти:**
> ps aux --sort=-%mem | head -10

## ❓ Самопроверка

1. **Как показать все процессы от всех пользователей?**
   👉 `ps aux`
2. **Как найти процессы, запущенные от root?**
   👉 `ps -U root -u root u`
3. **Почему `ps` может не показать руткит?**
   👉 Руткиты способны перехватывать системные вызовы и скрывать процессы от стандартных утилит.

## ps
> [!question]- Как посмотреть все процессы в системе с подробной информацией?
> `ps aux`


> [!question]- Как подсчитать количество процессов, запущенных от root?
> `ps -U root -u root --no-headers | wc -l`


> [!question]- Почему нельзя смешивать BSD-стиль (`aux`) и POSIX-стиль (`-U`) в одной команде `ps`?
> Когда `ps` видит BSD-опцию (например, `aux`), она переключается в BSD-режим и перестаёт корректно воспринимать POSIX-опции с дефисами. Фильтр не сработает, и вывод будет некорректным.
