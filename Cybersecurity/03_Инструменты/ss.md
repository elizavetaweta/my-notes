# 🌐 ss — статистика сетевых сокетов (современная замена netstat)

> [!abstract] Суть одной фразой
> `ss` (Socket Statistics) — это быстрая утилита для отображения информации о сетевых сокетах: открытых портах, установленных соединениях, слушающих сервисах. Она заменяет устаревшую команду `netstat` и входит в пакет `iproute2`. Для специалиста по ИБ это основной инструмент аудита сетевой активности хоста.

---

## 📌 Базовое использование

**Показать все слушающие (listening) TCP и UDP порты с номерами, без разрешения имён:**

> ss -tuln

- `-t` (**t**cp) — показать TCP-сокеты.
- `-u` (**u**dp) — показать UDP-сокеты.
- `-l` (**l**istening) — только слушающие (открытые) порты.
- `-n` (**n**umeric) — не преобразовывать IP-адреса и номера портов в имена (ускоряет вывод).

**Показать все установленные соединения (без слушающих):**

> ss -tan state established

---

## 🔑 Ключевые опции

- `-t` (**t**cp) — отфильтровать TCP-сокеты.
- `-u` (**u**dp) — отфильтровать UDP-сокеты.
- `-l` (**l**istening) — только сокеты, которые ожидают входящие соединения (открытые порты).
- `-a` (**a**ll) — все сокеты (listening + established + closed).
- `-n` (**n**umeric) — показывать IP-адреса и порты числами, без DNS-резолвинга.
- `-p` (**p**rocess) — показать, какой процесс (PID и имя) использует сокет.
- `-s` (**s**ummary) — вывести сводную статистику по протоколам.
- `-4` / `-6` — только IPv4 или только IPv6.
- `state` — фильтр по состоянию соединения: `established`, `time-wait`, `listen`, `syn-sent` и др.

**Найти процесс, который слушает порт 443:**

> ss -tlnp sport = :443

- `sport` — source port (локальный порт).

**Показать все TCP-соединения, установленные с конкретным IP:**

> ss -tan dst 192.168.1.100 или src 192.168.1.100

---

## 🕵️ Сценарии для специалиста по ИБ

### 1. Аудит открытых портов (какие службы торчат наружу)

> ss -tuln

Быстро увидеть SSH (22), HTTPS (443), СУБД (3306) и случайно открытые порты.

### 2. Поиск подозрительных соединений (обратный шелл, C2-канал)

> ss -tanp | grep -vE "(LISTEN|TIME-WAIT|ESTAB.*:22|ESTAB.*:443)"

Показывает активные соединения, исключая безобидные SSH и HTTPS. Обрати внимание на IP в колонке `Peer Address:Port`.

### 3. Проверка, какое приложение заняло порт

> ss -tlnp | grep :8080

Показывает, какой процесс слушает порт 8080 (возможно, подозрительный веб-сервер).

### 4. Сводка по протоколам для быстрой оценки

> ss -s

Выводит общее количество TCP, UDP сокетов и их состояния. Полезно для выявления аномалий (например, сотни сокетов в `TIME-WAIT`).

## 🆚 `ss` vs `netstat`

| Характеристика | `ss` | `netstat` |
|---|---|---|
| **Скорость** | Высокая (читает напрямую из ядра) | Низкая (читает `/proc`) |
| **Статус** | Современный стандарт | Устаревший (не рекомендуется) |
| **Фильтрация** | Богатый синтаксис (`state`, `sport`) | Ограниченная |
| **Зависимость** | Пакет `iproute2` (установлен по умолчанию) | Пакет `net-tools` (может отсутствовать) |

> [!note] Всегда используй `ss`, а не `netstat`
> `netstat` официально признан устаревшим. В новых дистрибутивах его может не быть.

## 🔗 Связи

- [[ip]] — настройка IP-адресов на интерфейсах (дополняет `ss`, показывая, на каком IP висит порт).
- [[iptables]] — фильтрация трафика, который идёт к этим портам.
- [[lsof]] — альтернативный способ узнать, какой процесс слушает порт.
- [[tcpdump]] — захват трафика для анализа того, что именно передаётся через соединения, найденные `ss`.
- [[Linux]] — основная ОС.

## ❓ Самопроверка

1. **Как посмотреть все открытые TCP-порты на сервере?**
   👉 `ss -tln`
2. **Как узнать, какой процесс слушает порт 3306 (MySQL)?**
   👉 `ss -tlnp sport = :3306`
3. **Чем `ss` лучше `netstat`?**
   👉 `ss` быстрее, поддерживает более гибкую фильтрацию и является современным стандартом. `netstat` устарел.
