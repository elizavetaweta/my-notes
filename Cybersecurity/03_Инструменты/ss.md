# 🌐 ss — Socket Statistics (современная замена netstat)

> [!abstract] Суть одной фразой
> `ss` (Socket Statistics) — быстрый инструмент для исследования сетевых сокетов: открытых портов, активных соединений, слушающих служб. Получает данные напрямую из ядра, заменяет устаревший `netstat` и входит в пакет `iproute2`. Для специалиста по ИБ это основной способ аудита сетевой активности хоста в реальном времени.

---

## 📌 Базовое использование

**Показать все слушающие TCP и UDP порты (без обратного разрешения имён):**

```bash
ss -tuln
```

- `-t` (**t**cp) — TCP-сокеты.
- `-u` (**u**dp) — UDP-сокеты.
- `-l` (**l**istening) — только сокеты, ожидающие входящие соединения (открытые порты).
- `-n` (**n**umeric) — отключить преобразование IP-адресов и портов в символьные имена (значительно ускоряет вывод).

**Показать все установленные соединения (состояние `ESTABLISHED`), исключая слушающие порты:**

```bash
ss -tan state established
```

- `-a` (**a**ll) — отобразить сокеты во всех состояниях, но в сочетании с фильтром `state` вывод ограничивается указанным состоянием.

---

## 🔑 Ключевые опции

| Флаг | Расшифровка | Назначение |
|------|-------------|------------|
| `-t` | **t**cp | Только TCP-сокеты |
| `-u` | **u**dp | Только UDP-сокеты |
| `-l` | **l**istening | Только слушающие сокеты (открытые порты) |
| `-a` | **a**ll | Все сокеты (listening, established, time-wait и др.) |
| `-n` | **n**umeric | Числовой вывод IP и портов, без DNS-резолвинга |
| `-p` | **p**rocess | Привязка к процессу (PID и имя программы) |
| `-s` | **s**ummary | Сводная статистика по протоколам |
| `-4` / `-6` | IP version | Только IPv4 или только IPv6 |
| `state` | состояние TCP | Фильтр по состоянию (`established`, `listen`, `time-wait`, `syn-sent` и др.) |
| `sport` / `dport` | **s**ource **p**ort / **d**estination **p**ort | Фильтр по локальному или удалённому порту |

**Пример. Найти процесс, слушающий порт 443:**

```bash
ss -tlnp sport = :443
```

Здесь `sport` — source port (локальный порт).

**Пример. Все TCP-соединения с участием конкретного IP-адреса:**

```bash
ss -tan dst 192.168.1.100
ss -tan src 192.168.1.100
```

## 🕵️ Сценарии для специалиста по ИБ

### 1. Аудит открытых портов (какие службы доступны извне)

```bash
ss -tuln
```

Мгновенно показывает SSH (22), HTTPS (443), СУБД (3306, 5432) и случайно открытые сервисы. Открытый порт — потенциальный вектор атаки.

### 2. Поиск подозрительных соединений (обратный шелл, C2-канал)

```bash
ss -tanp | grep -vE "(LISTEN|TIME-WAIT|ESTAB.*:22|ESTAB.*:443)"
```

Отображает активные TCP-сессии, исключая типичные легитимные SSH и HTTPS. Обращайте внимание на незнакомые IP в колонке `Peer Address:Port` и процессы с необычными именами.

### 3. Идентификация приложения, занявшего порт

```bash
ss -tlnp | grep :8080
```

Показывает PID и имя процесса, который слушает порт 8080. Позволяет выявить подозрительный веб-сервер или неавторизованный прокси.

### 4. Быстрая оценка состояния протоколов

```bash
ss -s
```

Выводит общее количество TCP, UDP сокетов и распределение по состояниям (ESTAB, TIME-WAIT, CLOSE-WAIT и т.д.). Аномально большое число сокетов в `TIME-WAIT` или `SYN-RECV` может указывать на проблемы с производительностью или DoS-атаку.

### 5. Расширенная фильтрация по состояниям TCP

```bash
ss -tan state time-wait
ss -tan state syn-recv
```

Позволяет прицельно исследовать сокеты в конкретных состояниях и обнаруживать аномалии: медленное закрытие соединений, SYN-флуд.

### 6. Проверка сетевой активности конкретного процесса

```bash
ss -tanp | grep 'pid=1337'
```

Мониторинг всех соединений, открытых подозрительным PID. Помогает при расследовании инцидентов.

## 🆚 `ss` vs `netstat`

| Характеристика   | `ss`                                      | `netstat`                                |
|------------------|-------------------------------------------|------------------------------------------|
| **Скорость**     | Высокая (чтение из подсистемы ядра)       | Низкая (разбор `/proc`)                  |
| **Статус**       | Современный стандарт                      | Устаревший (официально не рекомендуется) |
| **Фильтрация**   | Гибкий синтаксис (`state`, `sport`, `dport`) | Ограниченная                             |
| **Доступность**  | Пакет `iproute2` (установлен по умолчанию) | Пакет `net-tools` (может отсутствовать)  |

> [!note] Всегда используйте `ss`, а не `netstat`
> `netstat` официально признан устаревшим. В современных дистрибутивах его может не быть. `ss` работает быстрее и предоставляет больше возможностей для фильтрации.

## 🔗 Связи с другими инструментами

- [[ip]] — управление IP-адресами и сетевыми интерфейсами. Помогает понять, на каком конкретно IP висит обнаруженный сокет.
- [[iptables]] — фильтрация трафика, который направляется к открытым портам, выявленным `ss`.
- [[lsof]] — альтернативный способ определения процесса, занявшего порт: `lsof -i :443`.
- [[tcpdump]] — захват и анализ трафика, который передаётся через найденные `ss` соединения.

## 🧠 Значимость для меня как специалиста по ИБ

- Я знаю, что `ss -tuln` — первая команда при аудите периметра сервера. Каждый открытый порт — это сервис, который нужно проверить на обновления и корректность конфигурации.
- Я могу быстро обнаружить нежелательные соединения (C2-канал, reverse shell) с помощью `ss -tanp` и анализа нестандартных пар IP:порт.
- Я интерпретирую состояния сокетов: `LISTEN` — ожидание подключений, `ESTABLISHED` — активное соединение, `TIME-WAIT` — закрывающийся сокет. Это помогает в расследовании инцидентов и тюнинге системы.
- Я владею фильтрацией по `sport`, `dport` и `state`, что ускоряет локализацию проблемы в десятки раз по сравнению с ручным разбором вывода.

## 💬 Ответ на собеседовании (кратко)

> «`ss` — современная замена `netstat` для просмотра сетевых сокетов. Я использую `ss -tuln` для аудита открытых портов и `ss -tanp` для поиска подозрительных соединений. Фильтры `state`, `sport` и `dport` позволяют моментально находить нужную информацию. Поскольку `ss` читает данные напрямую из ядра, он работает значительно быстрее `netstat` и является стандартом де-факто в современных Linux-системах».
