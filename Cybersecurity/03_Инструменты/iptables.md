# 🛡️ iptables — межсетевой экран Linux

> [!abstract] Суть одной фразой
> `iptables` — это утилита командной строки для настройки встроенного в ядро [[Linux]] межсетевого экрана (Netfilter). Она позволяет фильтровать, перенаправлять и модифицировать сетевые пакеты. Для специалиста по ИБ это базовый инструмент защиты периметра на уровне хоста.

---

## 📌 Три главные цепочки (Chains)

`iptables` оперирует правилами, сгруппированными в цепочки:

| Цепочка | Когда срабатывает | Пример использования |
|---|---|---|
| **INPUT** | Пакеты, адресованные этому хосту | Защита входящих соединений (SSH, веб-сервер) |
| **OUTPUT** | Пакеты, отправленные с этого хоста | Ограничение исходящего трафика |
| **FORWARD** | Пакеты, проходящие через хост (маршрутизация) | Настройка шлюза, NAT |

У каждого правила есть **действие (target)**: `ACCEPT` (разрешить), `DROP` (тихо отбросить), `REJECT` (отклонить с уведомлением).

---

## 🔑 Базовые команды

**Посмотреть все правила (с номерами строк):**
> iptables -L -n -v --line-numbers

`-n` — не преобразовывать IP в имена (быстрее), `-v` — подробный вывод.

**Разрешить входящие соединения на порт 22 (SSH):**
> iptables -A INPUT -p tcp --dport 22 -j ACCEPT

**Разрешить всё от доверенного IP:**
> iptables -A INPUT -s 192.168.1.100 -j ACCEPT

**Заблокировать конкретный IP-адрес:**
> iptables -A INPUT -s 10.0.0.55 -j DROP

**Удалить правило по номеру (например, третье в цепочке INPUT):**
> iptables -D INPUT 3

**Сохранить правила (чтобы пережили перезагрузку):**
> iptables-save > /etc/iptables/rules.v4

## 🛡️ Типовая защитная конфигурация для веб-сервера
**Запретить всё по умолчанию**
>iptables -P INPUT DROP
iptables -P FORWARD DROP
iptables -P OUTPUT ACCEPT

**Разрешить уже установленные соединения**
>iptables -A INPUT -m state --state ESTABLISHED,RELATED -j ACCEPT

**Разрешить локальный интерфейс (loopback)**
>iptables -A INPUT -i lo -j ACCEPT

**Разрешить SSH (порт 22)**
>iptables -A INPUT -p tcp --dport 22 -j ACCEPT

**Разрешить HTTP и HTTPS**
>iptables -A INPUT -p tcp --dport 80 -j ACCEPT
iptables -A INPUT -p tcp --dport 443 -j ACCEPT


> [!note] Что здесь происходит
> Мы по умолчанию запрещаем всё входящее, затем точечно открываем нужные порты. Это принцип «белого списка» — стандарт для защиты серверов.

## 🧠 Значимость для меня как специалиста по ИБ

- Я знаю, что `iptables` — это первый рубеж защиты любого Linux-сервера. При аудите я всегда проверяю текущие правила (`iptables -L -n`).
- Я понимаю принцип «белого списка»: запрещено всё, кроме явно разрешённого. Это стандарт безопасной конфигурации.
- Я могу быстро заблокировать атакующий IP-адрес, настроить защиту от простого перебора паролей (rate limiting) и проверить, не открыты ли лишние порты.

## ❓ Самопроверка

1. **Как посмотреть все текущие правила iptables?**
   👉 `iptables -L -n -v`
2. **Как запретить всё входящее и открыть только порт 22?**
   👉 `iptables -P INPUT DROP`, затем `iptables -A INPUT -p tcp --dport 22 -j ACCEPT`
3. **Как заблокировать конкретный IP?**
   👉 `iptables -A INPUT -s IP_адрес -j DROP`
