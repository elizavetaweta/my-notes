# 📈 top — интерактивный монитор процессов и ресурсов

> [!abstract] Суть одной фразой
> `top` — это стандартная консольная утилита [[Linux]], показывающая запущенные процессы и потребление ресурсов (CPU, память) в реальном времени. Для специалиста по ИБ это основной инструмент быстрой оценки состояния системы: обнаружения аномальной нагрузки, подозрительных процессов и скрытых майнеров.

---

## 📌 Как запустить

> top

Выход из `top` — клавиша `q`.

Для однократного вывода (без интерактивного режима, удобно для скриптов):

> top -n 1 -b

---

## 🔍 Структура вывода

Верхняя часть — сводка по системе, нижняя — таблица процессов.

### Сводка по системе (первые строки)

> top - 14:32:10 up 45 days,  3:12,  2 users,  load average: 0.08, 0.15, 0.22
> Tasks: 187 total,   1 running, 186 sleeping,   0 stopped,   0 zombie
> %Cpu(s):  2.3 us,  1.0 sy,  0.0 ni, 96.5 id,  0.0 wa,  0.0 hi,  0.2 si,  0.0 st
> MiB Mem :   7842.3 total,   1245.6 free,   3210.4 used,   3386.3 buff/cache
> MiB Swap:   2048.0 total,   1980.0 free,     68.0 used.   4100.0 avail Mem

- `load average` — средняя нагрузка за 1, 5 и 15 минут. Если значение превышает количество ядер CPU — система перегружена.
- `us` (user) — процессы пользователя; `sy` (system) — ядро; `id` (idle) — простой; `wa` (wait) — ожидание ввода-вывода.
- `zombie` — процессы-зомби (завершены, но не приняты родителем). Большое количество — индикатор проблемы.
- `used` / `free` / `buff/cache` — состояние оперативной памяти.

### Таблица процессов (ключевые столбцы)

| Столбец | Значение | Зачем нужно ИБ-специалисту |
|---|---|---|
| **PID** | ID процесса | Идентифицировать процесс для `kill`, `lsof`, `strace` |
| **USER** | Владелец | Незнакомый пользователь, запускающий процесс — сигнал тревоги |
| **%CPU** | Потребление CPU | Процесс, забирающий > 80% CPU — возможный майнер |
| **%MEM** | Потребление памяти | Утечка памяти, скрытый процесс |
| **TIME+** | Суммарное процессорное время | Долго работающий процесс, запущенный злоумышленником |
| **COMMAND** | Команда запуска | Подозрительное имя (`[kworker/0:0]` нормально, `./xmr` — нет) |

## ⌨️ Горячие клавиши

| Клавиша | Действие |
|---|---|
| `q` | Выйти |
| `h` | Справка по всем клавишам |
| `1` | Показать нагрузку по каждому ядру CPU отдельно |
| `M` | Сортировать по использованию памяти (%MEM) |
| `P` | Сортировать по использованию CPU (%CPU) |
| `k` | Послать сигнал процессу (завершить) — запросит PID и сигнал |
| `u` | Фильтр по пользователю |
| `c` | Показать полный путь к команде |
| `V` | Отобразить процессы в виде дерева (forest view) |

---

## Шкала приоритетов

От `-20` (высший приоритет) до `19` (низший). По умолчанию процессы запускаются с `0`.

| Значение | Смысл |
|---|---|
| `-20` | Наивысший приоритет (процесс захватывает CPU) |
| `0` | Стандартный приоритет |
| `19` | Низший приоритет (максимально «вежливый» к другим) |



## 🕵️ Сценарии для специалиста по ИБ

**Быстрая оценка нагрузки на сервер:**
> top -n 1 -b | head -20

**Поиск самого прожорливого процесса (потребление CPU):**
Запустить `top`, нажать `P`.

**Проверка процессов конкретного пользователя:**
Запустить `top`, нажать `u`, ввести имя пользователя.

**Обнаружение процессов, запущенных из нестандартных папок:**
Запустить `top`, нажать `c` (показать полный путь). Искать процессы, запущенные из `/tmp`, `/dev/shm`, `/var/tmp`.

**Экспорт в файл для отчёта:**
> top -n 1 -b > top_snapshot.txt

## 🧠 Значимость для меня как специалиста по ИБ

- Я знаю, что `top` — это первое, что я открываю при подозрении на компрометацию: ищу процессы, потребляющие аномально много CPU или памяти, процессы с нестандартными именами, запущенные из `/tmp`.
- Я обращаю внимание на зомби-процессы: если их становится всё больше, это может говорить о проблемах в системе или о том, что вредоносный процесс порождает дочерние и не заботится о них.
- Я различаю легитимные процессы ядра (`[kworker]`, `[migration]`) и подозрительные (`./minerd`, `./xmrig`), умею фильтровать вывод.

## ❓ Самопроверка

1. **Как отсортировать процессы по использованию памяти?**
   👉 Нажать `M` в интерактивном режиме.
2. **Как показать полный путь к исполняемому файлу процесса?**
   👉 Нажать `c`.
3. **Как выгрузить однократный снимок `top` в файл?**
   👉 `top -n 1 -b > файл.txt`
4. **Что означает процесс со статусом `zombie`?**
   👉 Процесс завершился, но его родитель не считал код возврата. Много зомби — повод для диагностики.
