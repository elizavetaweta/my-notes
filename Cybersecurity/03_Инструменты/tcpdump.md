# 📡 tcpdump — перехват и анализ сетевого трафика

> [!abstract] Суть одной фразой
> `tcpdump` — это консольный анализатор сетевых пакетов. Он позволяет в реальном времени видеть, какие данные передаются через сетевые интерфейсы. Для специалиста по ИБ это основной инструмент для обнаружения атак, анализа подозрительного трафика и расследования инцидентов.

---

## 📌 Базовое использование

**Показать весь трафик на интерфейсе (требует root):**
> sudo tcpdump -i eth0

**Показать только пакеты, относящиеся к хосту:**
> sudo tcpdump host 192.168.1.100

**Показать только трафик на порт 22 (SSH):**
> sudo tcpdump port 22

**Сохранить трафик в файл для последующего анализа (pcap):**
> sudo tcpdump -w /tmp/capture.pcap

**Читать трафик из файла:**
> sudo tcpdump -r /tmp/capture.pcap

---

## 🔑 Ключевые опции

- `-i интерфейс` (**i**nterface) — указать интерфейс (`eth0`, `any` — все).
- `-n` (**n**umeric) — не преобразовывать IP-адреса в доменные имена (ускоряет вывод).
- `-nn` — двойной **n**umeric: не преобразовывать ни IP, ни порты (оставить всё в числовом виде).
- `-v`, `-vv`, `-vvv` (**v**erbose) — уровень подробности вывода: чем больше `v`, тем детальнее информация.
- `-c N` (**c**ount) — остановиться после захвата N пакетов.
- `-A` (**A**SCII) — показать содержимое пакета в текстовом виде (читаемый текст).
- `-X` (he**X** dump) — показать содержимое пакета в шестнадцатеричном и ASCII-виде.
- `-w файл` (**w**rite) — сохранить захваченные пакеты в файл (обычно с расширением `.pcap`), не выводя на экран.
- `-r файл` (**r**ead) — читать и анализировать ранее сохранённый файл захвата.
- `-s размер` (**s**naplen) — ограничить длину захватываемой части каждого пакета (`-s 0` — захватывать полностью).

> sudo tcpdump -i eth0 -nn port 443 -c 10

Покажет 10 пакетов HTTPS без DNS-резолвинга и имён портов.

## 🧬 Фильтрация трафика (BPF-выражения)

Операторы: `and` (&&), `or` (||), `not` (!).

**Фильтры по хостам, сетям, портам:**
```bash
# Трафик хоста (источник или получатель)
tcpdump host 10.0.0.5

# Трафик от конкретного источника
tcpdump src 192.168.1.100

# Трафик в определённую сеть
tcpdump dst net 10.0.0.0/24

# Трафик на порт 80 (HTTP) и от хоста 192.168.1.1
tcpdump 'port 80 and host 192.168.1.1'

# Всё, кроме SSH и HTTPS
tcpdump 'not port 22 and not port 443'
```

**По протоколам и флагам (важно для ИБ):**
```bash
# Только ICMP (пинги)
tcpdump icmp

# TCP-пакеты с флагом SYN (начало соединения)
tcpdump 'tcp[tcpflags] & (tcp-syn) != 0'

# TCP-пакеты с флагом SYN без ACK (сканирование портов)
tcpdump 'tcp[tcpflags] == tcp-syn'

# TCP-пакеты с флагом RST (сброс соединения)
tcpdump 'tcp[tcpflags] & (tcp-rst) != 0'
```

## 🕵️ Для специалиста по ИБ

- **Обнаружение подозрительных соединений:**  
  `tcpdump -i any -nn not port 22 and not port 443` — весь нестандартный трафик.
- **Поиск передачи паролей или токенов в открытом виде (HTTP, FTP, Telnet):**  
  `tcpdump -A port 21 or port 23 or port 80`  
  (`-A` выводит читаемый текст, если данные не зашифрованы).
- **Выявление сканирования портов:**  
  `tcpdump -nn 'tcp[tcpflags] == tcp-syn'` — только SYN-пакеты.
- **Сохранение улик:**  
  `tcpdump -i any -s 0 -w incident.pcap` — полный захват всех пакетов для последующего анализа.
- **Мониторинг DNS-запросов (обнаружение туннелирования/экcфильтрации):**  
  `tcpdump -nn port 53`

- `tcpdump` — стандарт де-факто для захвата трафика на Linux-серверах, даже без графической оболочки.
- Я могу быстро определить, не стучится ли сервер на известный вредоносный IP или не передаёт ли данные в открытом виде.
