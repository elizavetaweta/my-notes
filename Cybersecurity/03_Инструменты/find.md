# 🔍 find — поиск файлов и каталогов

> [!abstract] Суть одной фразой
> `find` — это команда для поиска файлов и каталогов по имени, типу, размеру, правам доступа, владельцу, времени изменения и другим критериям. Для специалиста по ИБ это основной инструмент аудита прав, поиска подозрительных файлов и автоматизации проверок.

В отличие от `ls`, который показывает содержимое одной папки, `find` рекурсивно обходит всё дерево каталогов и возвращает только то, что соответствует заданным условиям.

---

## 📌 Базовое использование

> find /путь/к/поиску -name "имя_файла"

Например, найти все файлы с именем `id_rsa` (закрытые ключи SSH) во всей системе:

> find / -name "id_rsa"

---
## 🔑 Основные флаги

- `-name "шаблон"` (**name**) — поиск по имени файла или папки. Регистр учитывается.  
  > find / -name "id_rsa"

- `-iname "шаблон"` (**i**nsensitive **name**) — то же, что `-name`, но без учёта регистра (ID_RSA, Id_Rsa и т.д.).

- `-type X` (**type**) — тип объекта: `f` — файл, `d` — папка, `l` — символическая ссылка.  
  > find /var/run -type s   # найти все сокеты

- `-perm права` (**perm**issions) — поиск по правам доступа.  
  `-perm 777` — точное совпадение; `-perm -u+w` — файлы, доступные владельцу для записи.  
  > find / -type f -perm 0777   # файлы, доступные всем на всё

- **SUID-файлы (потенциальная эскалация):** `find / -type f -perm -4000`
- **SGID-файлы:** `find / -type f -perm -2000`
- **Файлы, доступные всем на запись:** `find / -type f -perm -o+w`
- **Файлы с правами 777:** `find / -type f -perm 0777`
- 
- `-user имя` (**user**) — поиск по владельцу.  
  > find / -user shadowbunny

- `-group имя` (**group**) — поиск по группе-владельцу.

- `-size +N` (**size**) — поиск по размеру. `+100M` — больше 100 МБ, `-10k` — меньше 10 КБ.  
  > find /var/log -type f -size +50M


- `-exec команда {} \;` (**exec**ute) — выполнить команду над каждым найденным файлом. `{}` заменяется на путь к файлу, `\;` — конец команды.  
  > find /tmp -type f -name "*.log" -exec rm {} \;

- `-mtime N` (**m**odification **time**) — файлы, изменённые N дней назад. `-1` — за последние сутки, `+30` — старше 30 дней.  
  > find /etc -type f -mtime -1   # всё, что поменялось сегодня

**Примеры для аудита:**
> find /var/log -type f -mtime -1   # изменённые за последние 24 часа
> find /etc -type f -mtime +30     # не изменявшиеся больше месяца
## 🔢 Что означают `+`, `-` и число без знака в `-mtime`

Тест `-mtime N` (и аналогичные `-atime`, `-ctime`) сравнивает время последнего изменения файла с текущим моментом. Знак перед числом меняет логику сравнения:

- `-mtime -7` — файлы, изменённые **менее 7 дней назад** (последняя неделя).
- `-mtime +7` — файлы, изменённые **более 7 дней назад** (старше недели).
- `-mtime 7` (без знака) — файлы, изменённые **ровно 7 дней назад** (с точностью до суток).

> [!tip] Как запомнить
> Знак `-` (минус) означает «меньше, ближе к нам по времени». Знак `+` (плюс) — «больше, дальше в прошлое».

## 🔑 Поиск по типу файла

> find /путь/ -type f   # только обычные файлы
> find /путь/ -type d   # только каталоги
> find /путь/ -type l   # только символические ссылки

Поиск сокетов (потенциально опасных):

> find /var/run -type s

Типы файлов описаны в заметке [[Типы файлов в Linux]].

## 🔐 Поиск по правам доступа (аудит)

Самый важный сценарий для ИБ.

> find / -type f -perm 0777

Найдёт **все файлы в системе**, доступные кому угодно для чтения, записи и исполнения. Такие файлы — критическая находка.

Символьная запись:

> find / -type f -perm -o+w

Найдёт файлы, доступные для записи «остальным» (others).

Поиск файлов с SUID-битом (запускаются от имени владельца, потенциальная точка эскалации):

> find / -type f -perm -4000


## 🔐 Подробно о `-perm`: три режима, символы и цифры

Тест `-perm` ищет файлы с определёнными правами доступа. Его поведение зависит от **префикса** перед значением:

| Режим | Запись | Что означает | Пример | Что найдёт |
|---|---|---|---|---|
| **Точное совпадение** | `-perm число` | Права файла должны **строго совпадать** с указанными | `-perm 644` | Файлы с правами **ровно** `rw-r--r--` |
| **Все указанные биты установлены** | `-perm -число` | У файла должны быть **как минимум** указанные биты. Префикс `-` (минус) — «не меньше чем». | `-perm -444` | Файлы, у которых **все три категории** (`a`) имеют право `r` |
| **Любой из указанных битов установлен** | `-perm /число` | У файла должен быть установлен **хотя бы один** из указанных битов. Префикс `/` — «или». | `-perm /111` | Файлы, которые **кто‑нибудь** может выполнять |

### 🔤 Символьный синтаксис

Символьный режим удобен, когда нужно указать конкретную категорию (`u`, `g`, `o`). **Всегда используй префикс `-` или `/`** перед символьным выражением.

- `-perm -u=r` — у владельца есть как минимум право на чтение `r` (остальные могут быть любыми).
- `-perm -o=r` — у остальных есть как минимум право на чтение `r` (владелец и группа могут быть любыми).
- **`-perm /u=rw`**: у владельца есть **хотя бы один** из битов `r` или `w` (или оба). Файл с правами `-r--------` подойдёт, потому что есть `r`. Файл с `--w-------` тоже подойдёт, потому что есть `w`.
- `-perm u=rwx,g=rx,o=r` — права **строго** соответствуют этому набору, владелец имеет полные права, группа может читать и выполнять, остальные только читать.

### 🔢 Числовой синтаксис

Числовой синтаксис — сумма битов: `r=4`, `w=2`, `x=1`. Категория «остальные» (`o`) — третья цифра справа.

- `-perm -004` — у «остальных» обязательно есть право на чтение.
- `-perm -020` — у группы обязательно есть право на запись.
- `-perm -400` — у владельца обязательно есть право на чтение.

> [!tip] Как запомнить префиксы
> - **Минус (`-`)** → «как минимум» (≥). Файл должен иметь все указанные биты.
> - **Слэш (`/`)** → «или». Достаточно хотя бы одного из указанных битов.
> - **Без префикса** → «строго равно».

## 🔑 Поиск по владельцу и группе

> find / -user username   # файлы конкретного пользователя
> find / -group groupname  # файлы конкретной группы

---

## 🔑 Поиск по размеру

> find / -type f -size +100M   # файлы больше 100 МБ

Полезно при поиске «тяжёлых» артефактов (дампах памяти, украденных архивах).

---

## 🔑 Поиск по времени (для расследования инцидентов)

> find /var/log -type f -mtime -1   # изменённые за последние 24 часа
> find / -type f -atime -30         # файлы, к которым обращались за последние 30 дней

После взлома злоумышленник часто меняет файлы — поиск по времени помогает быстро найти следы.

---

## 🔑 Поиск с выполнением команды над результатами

> find /tmp -type f -name "*.sh" -exec ls -la {} \;

Находит все `.sh` файлы в `/tmp` и показывает их подробную информацию.

> find / -type f -perm 0777 -exec chmod 644 {} \;

Находит все файлы с правами `777` и исправляет их на `644` (осторожно!).

---

## 🔍 Особый случай: `\( ... \)` — группировка условий в `find`

В команде [[find]] скобки `\( ... \)` используются для группировки условий поиска. Они не имеют отношения к Bash-скобкам `( )` (подоболочка), а являются операторами самой команды `find`. Поскольку `(` и `)` — специальные символы Bash, их необходимо **экранировать** обратным слэшем, чтобы они были переданы `find`, а не обработаны оболочкой.

```bash
>find /usr/bin /usr/sbin -type f \( -perm -4000 -o -perm -2000 \)
```


Здесь `\( ... \)` группирует условия: `-perm -4000` (SUID) **ИЛИ** (`-o`) `-perm -2000` (SGID). Без скобок `find` интерпретировал бы логику иначе из-за приоритета операторов.

| Скобки | Где используются | Назначение |
|---|---|---|
| `\( ... \)` | Внутри команды `find` | Группировка условий поиска |
| `( ... )` | Bash | Подоболочка (subshell) |
| `{ ... }` | Bash | Группировка команд в текущей оболочке |

## 🧠 Значимость для меня как специалиста по ИБ

- Я знаю, что `find` — это первый инструмент после `ls` при аудите: он показывает системные проблемы (права `777`, SUID-файлы) и следы атакующего.
- Я могу быстро найти все файлы, изменённые за последние сутки, чтобы локализовать инцидент.
- Я помню, что `find -exec` может быть опасен: неправильная команда может повредить систему. Всегда проверяю вывод `find` без `-exec` перед массовыми изменениями.
