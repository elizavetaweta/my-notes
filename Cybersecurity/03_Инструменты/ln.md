# 🔗 ln — создание ссылок на файлы

> [!abstract] Суть одной фразой
> `ln` (Link) — это команда для создания ссылок на файлы и папки. Без опций она создаёт **жёсткую ссылку** (второе имя того же файла), а с флагом `-s` — **символическую ссылку** (файл-указатель на цель).

Для специалиста по ИБ понимание `ln` важно, потому что злоумышленники могут использовать ссылки для маскировки файлов, а администраторы — для удобной организации конфигураций и дублирования данных без расхода места.

---

## 📌 Базовое использование

**Создать жёсткую ссылку:**
> ln /путь/к/исходному_файлу имя_ссылки

**Создать символическую ссылку:**
> ln -s /путь/к/цели имя_ссылки

---

## 🔑 Жёсткая ссылка (Hard Link)

> ln /etc/passwd /tmp/passwd_copy

После этой команды `/tmp/passwd_copy` и `/etc/passwd` — это **два равноправных имени**, указывающих на одни и те же данные (один inode). Удаление одного имени не удаляет данные, пока есть хотя бы одна ссылка.

**Особенности:**
- Нельзя создать на папку.
- Нельзя создать между разными файловыми системами (разделами).

---

## 🔑 Символическая ссылка (Symbolic Link, Symlink)

> ln -s /var/log/syslog /tmp/syslog_link

После этой команды `/tmp/syslog_link` — это отдельный файл типа `l`, который хранит **путь** к `/var/log/syslog`. Если удалить исходный файл, ссылка останется, но станет «битой» (dangling).

**Особенности:**
- Можно создать на файл или папку.
- Может указывать на цель в другой файловой системе.

---

## 🔑 Основные опции

- `-s` — создать символическую ссылку (symbolic).
- `-f` (force) — перезаписать существующий файл с таким же именем.
- `-n` — не следовать по символической ссылке, если целевой путь сам является ссылкой (используется с `-f`).

> ln -sf /новый/путь старая_ссылка

Обновит существующую символическую ссылку, чтобы она указывала на новый путь.

---

## 🕵️ Примеры для специалиста по ИБ

**Создать символическую ссылку на лог-файл для быстрого доступа:**
> ln -s /var/log/nginx/access.log ~/nginx_access.log

Теперь можно анализировать лог веб-сервера прямо из домашней папки.

**Проверить подозрительные ссылки в `/tmp`:**
> ls -la /tmp | grep "^l"

Злоумышленники часто создают симлинки в `/tmp` для перехвата данных или обхода ограничений.

**Найти все жёсткие ссылки на конкретный файл (по inode):**
> find / -samefile /etc/passwd

Покажет, не создал ли кто-то скрытую копию файла паролей под другим именем.

---

## 💬 Ответ на собеседовании (кратко)

> «`ln` создаёт ссылки. Без флагов — жёсткую ссылку, второе имя того же файла. С флагом `-s` — символическую ссылку, указатель на путь. Симлинки видны в `ls -la` как `l -> target`. Жёсткие ссылки нельзя создать на папку и между разными разделами».

## ❓ Самопроверка

1. **Как создать символическую ссылку на папку `/var/log` в домашней директории?**
   👉 `ln -s /var/log ~/logs`
2. **Чем `ln file link` отличается от `ln -s file link`?**
   👉 Первая создаёт жёсткую ссылку (второе имя файла), вторая — символическую (указатель на путь).
3. **Как проверить, не осталось ли жёстких ссылок на файл после его удаления?**
   👉 `find / -samefile имя_файла` — покажет все оставшиеся имена этого inode.
