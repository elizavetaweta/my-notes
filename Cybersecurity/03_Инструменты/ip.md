# 🌍 ip — управление сетью, маршрутизацией и соседями

> [!abstract] Суть одной фразой
> `ip` — это современная многофункциональная команда для управления сетевыми интерфейсами, IP-адресами, таблицами маршрутизации, ARP-кэшем и туннелями. Она полностью заменяет устаревшие `ifconfig`, `route`, `arp` и другие. Для специалиста по ИБ это основной инструмент диагностики сети.

---

## 📌 Структура команды

> ip [OBJECT] [COMMAND]

`ip` не использует классические флаги вроде `-a` или `-l`. Вместо этого он работает с **объектами** (object) — словами, которые указывают, чем именно нужно управлять.

**Основные объекты:**
- `addr` (**addr**ess) — IP-адреса на интерфейсах (просмотр, добавление, удаление). Сокращение: `a`.
- `link` (**link**) — параметры канального уровня: состояние интерфейса, MAC-адрес, MTU. Сокращение: `l`.
- `route` (**route**) — таблица маршрутизации (просмотр, добавление, удаление маршрутов). Сокращение: `r`.
- `neigh` (**neigh**bor) — ARP-таблица (кэш соседей). Сокращение: `n`.

## 🔑 Базовые команды для аудита и диагностики

**Посмотреть IP-адреса всех интерфейсов:**
> ip addr show
> ip a

## 🔍 Расшифровка флагов состояния интерфейса

- `LOOPBACK` — виртуальный интерфейс «петли» (127.0.0.1).
- `UP` — интерфейс административно включён (`ip link set ... up`).
- `LOWER_UP` — физический линк активен (есть кабель или сигнал).
- `NO-CARRIER` — нет физического подключения (кабель не вставлен).
- `state UP` — интерфейс полностью работоспособен.
- `state DOWN` — интерфейс не работает (нет кабеля, сигнала или выключен).
- `state UNKNOWN` — типично для loopback и VPN-туннелей (нормально).
- `state DORMANT` — интерфейс готов, но ожидает внешнего события (например, подключения к Wi-Fi сети).
- `BROADCAST` — поддерживает широковещательную рассылку.
- `MULTICAST` — поддерживает групповую рассылку.
- `POINTOPOINT` — соединение типа «точка-точка» (VPN, туннели).
- `NOARP` — протокол ARP не используется (VPN, туннели).

**Посмотреть состояние интерфейсов (включены/выключены, MAC):**
> ip link show
> ip l

**Таблица маршрутизации:**
> ip route show
> ip r

**ARP-таблица (кто с каким MAC и IP сейчас общался):**
> ip neigh show

## 🔑 Полезные действия

**Добавить IP-адрес на интерфейс:**
> ip addr add 192.168.1.100/24 dev eth0

**Удалить IP-адрес:**
> ip addr del 192.168.1.100/24 dev eth0

**Поднять/опустить интерфейс:**
> ip link set eth0 up
> ip link set eth0 down

**Очистить ARP-кэш (после смены IP на шлюзе):**
> ip neigh flush all

## 🕵️ Примеры для специалиста по ИБ

**Проверить, не появились ли «левые» IP на интерфейсах (признак компрометации):**
> ip a | grep inet

**Проверить MAC-адрес шлюза (не подменён ли он, ARP-spoofing):**
> ip neigh show 192.168.1.1

**Проверить, не добавлены ли подозрительные маршруты (перехват трафика):**
> ip route show | grep -v default
