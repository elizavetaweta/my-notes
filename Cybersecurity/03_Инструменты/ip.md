# 🌍 ip — сетевая диагностика и управление для ИБ

> [!abstract] Суть
> `ip` — универсальный инструмент для настройки и аудита сети в Linux: IP-адреса, интерфейсы, маршруты, ARP, туннели. Полностью заменяет устаревшие `ifconfig`, `route`, `arp`. Для специалиста по информационной безопасности — основной инструмент оперативной диагностики, поиска аномалий и расследования инцидентов.

---

## 📌 Синтаксис и объекты

Команда `ip` не использует классические ключи; вместо них применяются **объекты** (разделы управления).  
Формат: `ip [ ОБЪЕКТ ] КОМАНДА [ ПАРАМЕТРЫ ]`

**Основные объекты для повседневного аудита:**
- `addr` (или `a`) — IP-адреса на интерфейсах.
- `link` (или `l`) — параметры канального уровня (состояние, MAC, MTU).
- `route` (или `r`) — таблица маршрутизации.
- `neigh` (или `n`) — ARP/NDP-таблица (соседи).

**Дополнительно для углублённого анализа:**
- `monitor` — отслеживание изменений в реальном времени (полезно для обнаружения подозрительной активности).
- `netns` — управление сетевыми пространствами имён (песочницы).
- `tuntap` — работа с туннельными интерфейсами (VPN, пентест).

Большинство команд поддерживают опцию `-json` для машинной обработки вывода (легко интегрировать в скрипты мониторинга).

## 🔍 Быстрая диагностика (must‑know)

### 1. IP-адреса
```bash
ip addr show        # все IP на всех интерфейсах
ip a                # кратко
```

### 2. Состояние интерфейсов
```bash
ip link show        # MAC, статус, MTU
ip l
```

**Расшифровка ключевых флагов состояния** (сразу видно, есть ли физический линк):
- `UP` – интерфейс административно включён (`ip link set dev eth0 up`).
- `LOWER_UP` – физический уровень активен (кабель вставлен, сигнал есть).
- `NO-CARRIER` – кабель не подключён или нет сигнала.
- `state UP` – интерфейс полностью работоспособен.
- `state DOWN` – интерфейс отключён (административно или физически).
- `state UNKNOWN` – типично для loopback, туннелей (нормально).
- `state DORMANT` – ожидание внешнего события (например, подключение к Wi‑Fi).
- `BROADCAST`, `MULTICAST` – типы рассылки.
- `POINTOPOINT` – соединение «точка‑точка» (VPN, PPP).
- `NOARP` – ARP не используется (туннели).
- `PROMISC` – неразборчивый режим (⚠️ часто признак сниффинга/атаки).

**Проверка promiscuous-режима:**
```bash
ip link show | grep PROMISC
```

### 3. Таблица маршрутизации
```bash
ip route show       # вся таблица
ip r
```
[[ip route]] — детальный разбор маршрутизации в отдельной заметке.

### 4. ARP/NDP таблица
```bash
ip neigh show       # кэш соседей (IP ↔ MAC)
ip n
```

## 🔧 Практические действия

**Добавить/удалить IP-адрес:**
```bash
ip addr add 192.168.1.100/24 dev eth0
ip addr del 192.168.1.100/24 dev eth0
```

**Включить/выключить интерфейс:**
```bash
ip link set eth0 up
ip link set eth0 down
```

**Работа с маршрутами:**
```bash
ip route add 10.0.0.0/8 via 192.168.1.1   # добавить маршрут
ip route del 10.0.0.0/8                   # удалить
ip route flush cache                      # сбросить кэш маршрутизации (после изменений)
```

**Статическая ARP-запись (защита от ARP‑spoofing для критичных хостов):**
```bash
ip neigh add 192.168.1.1 lladdr aa:bb:cc:dd:ee:ff dev eth0 nud permanent
```
После этого MAC-адрес шлюза будет зафиксирован, и атакующий не сможет «отравить» кэш (требует ручного обновления при смене оборудования).

**Очистить ARP-кэш (после миграций или при подозрении на атаку):**
```bash
ip neigh flush all
```

**Мониторинг сетевых событий в реальном времени (ИБ‑аналитика):**
```bash
ip monitor all | grep -E 'addr|route|neigh|link'
```
Позволяет ловить появление новых IP, изменение MAC-адреса шлюза, добавление странных маршрутов.

## 🕵️‍♂️ Сценарии для специалиста по ИБ

1. **Поиск несанкционированных IP‑адресов на интерфейсах (компрометация, backconnect-шеллы):**
   ```bash
   ip a | grep inet
   ```
   Сравниваем с эталонным списком разрешённых адресов.

2. **Обнаружение ARP‑spoofing (подмена шлюза):**
   ```bash
   ip neigh show 192.168.1.1
   ```
   Сверяем MAC с реальным (например, с наклейки на устройстве или документации). Повторяем несколько раз, обращая внимание на изменение MAC.

3. **Выявление подозрительных маршрутов (перехват трафика через сторонний шлюз):**
   ```bash
   ip route show | grep -v default
   ```
   Любой маршрут, ведущий трафик в неожиданную сеть через незнакомый шлюз, — повод для немедленного расследования.

4. **Проверка включения promiscuous-режима (запущенный сниффер):**
   ```bash
   ip link show | grep PROMISC
   ```
   Если интерфейс в режиме PROMISC, а вы не запускали tcpdump/Wireshark, — возможна работа вредоносного ПО.

5. **Экспресс-аудит изменений за последнее время:**
   ```bash
   ip monitor all > /var/log/net_monitor.log &  # запустить фоновый мониторинг
   ```
   Позднее анализировать лог на предмет необъяснимых событий.

## 🧠 Значимость для меня как специалиста по ИБ
- `ip` — это мой основной «сетевой фонарик»: с него начинается любой осмотр хоста при расследовании.
- Я регулярно проверяю, не появились ли новые IP, не изменилась ли таблица маршрутизации, верен ли MAC шлюза.
- С помощью `ip monitor` могу организовать примитивную, но эффективную систему обнаружения аномалий без дополнительных агентов.
- Команда позволяет не только диагностировать, но и быстро реагировать: удалить левый адрес, принудительно прописать правильного соседа, сбросить отравленный ARP-кэш.

> «`ip` — это современная замена `ifconfig`, `route` и `arp`. В ежедневной работе использую `ip addr` для просмотра IP, `ip link` для состояния интерфейсов (в том числе поиск promiscuous-режима), `ip route` для проверки маршрутов и `ip neigh` для контроля ARP-таблицы. При аудите и расследовании инцидентов в первую очередь смотрю на наличие подозрительных адресов, неожиданных маршрутов и изменения MAC-адреса шлюза. Владею также `ip monitor` для мониторинга сетевых событий в реальном времени».
