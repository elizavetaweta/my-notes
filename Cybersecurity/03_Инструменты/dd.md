# 💿 dd — низкоуровневое копирование и перезапись данных

> [!abstract] Суть одной фразой
> `dd` (Data Duplicator) — это утилита для побайтового копирования данных между файлами, устройствами и разделами. В отличие от [[cp]], она работает на уровне «сырых» блоков, игнорируя файловую систему. Для специалиста по ИБ `dd` — основной инструмент для создания точных образов дисков при расследовании инцидентов и безопасной перезаписи носителей.

> [!danger] «Data Destroyer»
> Опечатка в имени выходного файла (`of`) может необратимо уничтожить важные данные. Всегда **дважды** проверяй, куда направляется запись, прежде чем нажать Enter.

---
## 🧠 Что значит «копирование на уровне сырых блоков»

Обычные команды (`cp`, `mv`) работают через **файловую систему** — они видят только то, что числится в оглавлении диска (файлы и папки). Свободное место и удалённые, но ещё не перезаписанные данные для них невидимы.

`dd` работает на уровень ниже — с **блоками** (секторами) диска напрямую, не обращаясь к оглавлению.

**Аналогия с книгой:**
- `cp` — библиотекарь: копирует главу по названию из оглавления.
- `dd` — сканер: переснимает каждую страницу подряд, включая пустые, грязные и вырванные, но всё ещё видимые под ультрафиолетом.

Именно поэтому `dd` незаменим для создания точных образов дисков при расследовании: он захватывает даже те данные, которые злоумышленник пытался удалить.


## 📌 Базовое использование

> dd if=/dev/sda of=/evidence/disk.img bs=4M status=progress

- `if` (**i**nput **f**ile) — откуда читаем (диск, раздел, файл-образ).
- `of` (**o**utput **f**ile) — куда пишем (файл-образ, другой диск).
- `bs` (**b**lock **s**ize) — размер блока данных за одну операцию. Влияет на скорость: `4M` — хорошее значение для больших дисков.
- `status=progress` — показывать прогресс копирования.

---

## 🔑 Ключевые опции

- `if=...` (**i**nput **f**ile) — источник данных (можно `/dev/urandom`, `/dev/zero`, `/dev/sda`).
- `of=...` (**o**utput **f**ile) — целевой файл или устройство.
- `bs=N` (**b**lock **s**ize) — размер блока (по умолчанию 512 байт, увеличить до `1M`‑`4M` для скорости).
- `count=N` — скопировать только N блоков (ограничить объём).
- `conv=sync,noerror` — при ошибках чтения дополнять блок нулями (`sync`) и продолжать (`noerror`). Используется для снятия образа с повреждённого диска.
- `status=progress` — показывать прогресс (доступно в современных версиях).

---

## 🕵️ Сценарии для специалиста по ИБ

### 1. Создание точного образа диска при расследовании (форензика)

> dd if=/dev/sda of=/evidence/disk.img bs=4M status=progress conv=sync,noerror

Образ можно затем анализировать, не трогая оригинальный носитель. Для сжатия образа «на лету»:

> dd if=/dev/sda bs=4M conv=sync,noerror | gzip -c > /evidence/disk.img.gz

### 2. Перезапись диска случайными данными перед списанием

> dd if=/dev/urandom of=/dev/sdb bs=4M status=progress

- `/dev/urandom` — источник криптографически стойких случайных данных.
- После такой перезаписи восстановить информацию практически невозможно (для HDD; для SSD — см. [[Безопасное стирание данных на SSD]]).

### 3. Обнуление диска (заполнение нулями)

> dd if=/dev/zero of=/dev/sdb bs=4M status=progress

Быстрее, чем случайными данными, но хуже скрывает факт перезаписи.

### 4. Создание загрузочной флешки из ISO-образа

> dd if=ubuntu.iso of=/dev/sdb bs=4M status=progress

После записи флешка готова к загрузке.

### 5. Безопасное удаление отдельного файла (альтернатива `shred`)

> dd if=/dev/urandom of=secret.txt bs=1M count=1

Перезапишет первый мегабайт файла случайными данными. Однако `shred` делает это удобнее и тщательнее.

## 🆚 `dd` vs `cp`

| Характеристика | `dd` | `cp` |
|---|---|---|
| **Уровень работы** | Блочный (сырые сектора) | Файловый (через файловую систему) |
| **Копирование разделов** | Да (`/dev/sda1`) | Нет |
| **Копирование в файл-образ** | Да | Нет |
| **Сохранение метаданных** | Нет (копирует только байты) | Да (с флагом `-p`) |
| **Прогресс** | `status=progress` | `-v` (только имена) |

## Современные альтернативы (почему dd используют реже)

В повседневных задачах обычные пользователи и администраторы часто заменяют dd более специализированными и безопасными утилитами:
- Для создания загрузочных флешек: Используют Rufus, BalenaEtcher или консольный ventoy. Они имеют защиту от случайной перезаписи системного диска.
- Для клонирования дисков: Применяют Clonezilla или Partclone. В отличие от dd, они копируют только занятые блоки, а не весь пустой объем диска, что экономит кучу времени.
- Для копирования с поврежденных дисков: Используют ddrescue. Она работает «умнее», собирая данные сначала со здоровых секторов, а потом возвращаясь к поврежденным.

## 🔗 Связи

- [[shred]] — безопасное удаление отдельных файлов.
- [[Безопасное стирание данных на SSD]] — почему `dd` не панацея для твердотельных накопителей.
- [[cp]] — файловое копирование.
- [[cat]] — ещё один способ копирования устройств (`cat /dev/sda > /dev/sdb`), но без контроля размера блока.
- [[lsblk]], [[fdisk]] — узнать имена устройств перед `dd`.
- [[VeraCrypt]], [[LUKS]] — полное шифрование диска как альтернатива перезаписи.

## 🧠 Значимость для меня как специалиста по ИБ

- Я знаю, что `dd` — это стандарт для снятия образов дисков при расследовании инцидентов. Полученный образ можно монтировать или анализировать в инструментах для расследования инцидентов (Forensics-инструментах).
- Я понимаю, что `dd` не различает файлы и свободное место — он копирует всё, включая удалённые данные, которые ещё не перезаписаны. Это делает его незаменимым для форензики.
- Я всегда проверяю `of=` перед запуском, потому что ошибка может уничтожить важные доказательства.

## ❓ Самопроверка

1. **Как создать образ диска `/dev/sda` в файл `/backup/sda.img`?**
   👉 `dd if=/dev/sda of=/backup/sda.img bs=4M status=progress`
2. **Чем `dd` принципиально отличается от `cp`?**
   👉 `dd` работает на уровне блоков, игнорируя файловую систему, и может копировать целые разделы и устройства. `cp` работает с файлами и папками.
3. **Почему `dd` называют «Data Destroyer»?**
   👉 Потому что ошибка в параметре `of` может необратимо перезаписать важные данные, и их нельзя будет восстановить.
