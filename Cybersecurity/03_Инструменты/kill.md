# 💀 kill — завершение процесса

> [!abstract] Суть одной фразой
> `kill` отправляет сигнал процессу. Чаще всего используется для принудительного завершения, но умеет и «мягко» просить процесс завершиться. Для специалиста по ИБ это инструмент остановки вредоносных процессов и перезагрузки конфигураций.

---

## 📌 Базовое использование

**Завершить процесс (по PID):**
> kill 12345

**Принудительно завершить (сигнал KILL):**
> kill -9 12345

**«Мягкое» завершение с сохранением данных (сигнал TERM, по умолчанию):**
> kill -15 12345

**Перезагрузить конфигурацию процесса (сигнал HUP):**
> kill -HUP 12345

---

## 🔑 Полезные сигналы

| Сигнал | Номер | Действие |
|---|---|---|
| `SIGTERM` | 15 | Мягкое завершение (процесс может сохранить данные и закрыться) |
| `SIGKILL` | 9 | Жёсткое завершение (ядро немедленно убивает процесс) |
| `SIGHUP` | 1 | Hangup — часто используется для перезагрузки конфигурации |
| `SIGSTOP` | 19 | Приостановить процесс (нельзя игнорировать) |
| `SIGCONT` | 18 | Продолжить остановленный процесс |

**Список всех сигналов:**
> kill -l

---

## 🔑 Завершение по имени — `killall`

> killall -9 имя_процесса

---

## 🕵️ Для специалиста по ИБ

- Обнаружив подозрительный процесс, я сначала анализирую его (`ps`, `lsof`, `ls -la /proc/PID`), а затем завершаю. `kill -9` — крайняя мера, потому что процесс не успеет закрыть файлы или удалить свои артефакты.
- `kill -HUP` использую для перезагрузки конфигурации легитимных служб без перезапуска.

---

> «`kill` отправляет сигнал процессу. По умолчанию — SIGTERM (15) для мягкого завершения. `kill -9` — безусловное уничтожение, использую только когда процесс завис и не реагирует. Перед этим собираю улики».

## ❓ Самопроверка

1. **Как принудительно завершить процесс?**
   👉 `kill -9 PID`
2. **Как перезагрузить конфигурацию nginx без разрыва соединений?**
   👉 `kill -HUP $(cat /var/run/nginx.pid)`
3. **Чем опасен `kill -9` при расследовании инцидента?**
   👉 Процесс не успевает закрыть файлы, удалить временные данные, и можно потерять часть улик.
