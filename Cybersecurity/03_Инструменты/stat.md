# 📊 stat — подробная информация о файле и его метаданных

> [!abstract] Суть одной фразой
> `stat` (Status) — это команда, которая выводит **все метаданные** файла или папки: размер, права, владельца, номера inode и, самое главное, **три временные метки** (atime, mtime, ctime). Для специалиста по ИБ это основной инструмент выявления таймстомпинга, потому что одну из меток (`ctime`) невозможно подделать через [[touch]].

---

## 📌 Базовое использование

> stat filename.txt

Выведет полную информацию о файле.

> stat /etc/shadow

Покажет метаданные файла паролей.

---

## 📐 Форматированный вывод (`-c`)

Флаг `-c` (**c**ustom) позволяет задать шаблон вывода, в котором спецификаторы `%...` заменяются на конкретные значения из метаданных файла. Это удобно для скриптов и отчётов, когда не нужна вся информация, а только несколько полей.

**Самые полезные спецификаторы для аудита:**

| Спецификатор | Значение | Пример вывода |
|---|---|---|
| `%A` | Права доступа в символьном виде (**A**ccess rights) | `-rw-r--r--` |
| `%a` | Права доступа в восьмеричном виде | `644` |
| `%U` | Имя владельца (**U**ser) | `root` |
| `%G` | Имя группы (**G**roup) | `shadow` |
| `%n` | Имя файла (**n**ame) | `/etc/shadow` |
| `%y` | Время последнего изменения (mtime) | `2026-05-27 14:30:00` |
| `%z` | Время последнего изменения метаданных (ctime) | `2026-05-27 14:30:00` |

**Пример для аудита критических файлов:**

> stat -c '%A %U %G %n' /etc/shadow /etc/sudoers /etc/ssh/sshd_config

Выведет три строки вида:
> -rw-r----- root shadow /etc/shadow
> -r--r----- root root /etc/sudoers
> -rw-r--r-- root root /etc/ssh/sshd_config

> [!note] Почему `stat`, а не `ls`
> `ls -la` выводит много лишнего, и его формат может отличаться в разных системах. `stat -c` даёт ровно те поля, которые нужны, в предсказуемом порядке.



## 🔍 Как читать вывод

Пример вывода для `/etc/shadow`:

>   File: /etc/shadow
>   Size: 1234        Blocks: 8          IO Block: 4096   regular file
> Device: 8,1   Inode: 654321      Links: 1
> Access: (0640/-rw-r-----)  Uid: (    0/    root)   Gid: (   42/  shadow)
> Access: 2025-05-20 08:15:30.123456789 +0000
> Modify: 2025-05-19 22:10:05.987654321 +0000
> Change: 2025-05-19 22:10:05.987654321 +0000

Разбор ключевых строк:

| Строка | Что означает |
|---|---|
| **Size** | Размер файла в байтах |
| **Inode** | Номер индексного дескриптора (см. [[inode]]) |
| **Access: (0640/-rw-r-----)** | Права доступа в цифровом и символьном виде |
| **Uid / Gid** | Числовой и текстовый идентификатор владельца и группы |
| **Access** | **atime** — время последнего доступа (чтения) к файлу |
| **Modify** | **mtime** — время последнего изменения **содержимого** файла |
| **Change** | **ctime** — время последнего изменения **метаданных** (прав, владельца, числа ссылок) |

---

## ⏰ Три временные метки и их значение для ИБ

| Метка | Команда | Что фиксирует | Можно ли подделать `touch`? |
|---|---|---|---|
| **atime** | Access time | Последнее чтение файла | Да, `touch -a` |
| **mtime** | Modify time | Последнее изменение содержимого | Да, `touch -m` |
| **ctime** | Change time | Последнее изменение метаданных (прав, владельца) | **НЕТ** |

> [!danger] Ключевой момент
> `ctime` обновляется только ядром при изменении метаданных. Если злоумышленник подделал `atime` и `mtime` через `touch`, но при этом менял права (`chmod`) или владельца (`chown`), `ctime` будет отличаться. Это и выдаёт таймстомпинг.

---
## 🔬 ctime — «неподкупная» метка

**ctime (Change Time)** — это время последнего изменения **метаданных** файла: прав доступа, владельца, количества жёстких ссылок. В отличие от mtime и atime, ctime **нельзя** подделать через [[touch]].

| Действие | Изменяет mtime? | Изменяет ctime? |
|---|---|---|
| Изменить содержимое файла | Да | Да |
| Изменить права (`chmod`) | Нет | **Да** |
| Сменить владельца (`chown`) | Нет | **Да** |
| Создать жёсткую ссылку (`ln`) | Нет | **Да** |
| Подделать метку через `touch -t` | Да (подделывается) | Да, но **реальным** временем выполнения `touch` |

> [!danger] Ключевой индикатор таймстомпинга
> Если злоумышленник подделал `mtime` через `touch -t`, `ctime` всё равно обновится текущим временем. Расхождение между `mtime` (далеко в прошлом) и `ctime` (недавнее) — главный признак подделки временных меток.

`ctime` обновляется **ядром** автоматически при любом изменении метаданных. Её нельзя установить произвольно — поэтому она служит «неподкупным свидетелем» при расследовании инцидентов.


## 🕵️ Сценарии для специалиста по ИБ

### 1. Выявление таймстомпинга

Злоумышленник заменил вредоносный скрипт и подделал его дату:

> touch -t 202401010000.00 /tmp/backdoor.sh
> stat /tmp/backdoor.sh

Если `Modify` показывает 1 января 2024 года, а `Change` — сегодняшнюю дату, это значит, что временные метки были подделаны (`touch` обновил и `ctime`, но если после `touch` кто-то менял права или владельца, `ctime` уйдёт вперёд).

### 2. Поиск недавно изменённых файлов

> find /etc -type f -newer /etc/passwd

Покажет файлы, изменённые позже, чем `/etc/passwd`. В сочетании со `stat` можно понять, **что именно** менялось.

### 3. Сравнение меток для поиска аномалий

Если `atime` старше `mtime` — файл давно не читали, но недавно изменяли. Если `mtime` старше `ctime` — содержимое не меняли, но меняли права или владельца (подозрительно для системных файлов).

## 🆚 `stat` vs `ls -la`

| Что показывает | `ls -la` | `stat` |
|---|---|---|
| **Права и владелец** | Да | Да |
| **Размер** | Да | Да |
| **mtime** (последнее изменение) | Да (колонка с датой) | Да |
| **atime** (последний доступ) | Нет | Да |
| **ctime** (изменение метаданных) | Нет | Да |
| **Номер inode** | Да (с флагом `-i`) | Да |

> [!note] Когда что использовать
> Для быстрого взгляда — `ls -la`. Для детективного расследования — только `stat`.

## 🔗 Связи

- [[touch]] — изменение временных меток (в том числе злоумышленником).
- [[ls]] — быстрый просмотр прав и mtime.
- [[inode]] — номер inode, который показывает `stat`.
- [[find]] — поиск файлов по временным меткам (`-mtime`, `-newer`).
- [[Linux]] — основная ОС.

## 🧠 Значимость для меня как специалиста по ИБ

- Я знаю, что `stat` — главный инструмент проверки подлинности временных меток. На собеседовании я всегда упоминаю `ctime` как маркер, который нельзя подделать через `touch`.
- При расследовании инцидента я сверяю `Modify` и `Change`: если `Change` новее `Modify`, это значит, что файл не редактировали, но меняли его метаданные — возможный след атакующего.
- Я могу быстро собрать метаданные по всем критичным файлам и сравнить их с эталонными значениями.

## 💬 Ответ на собеседовании (кратко)

> «`stat` показывает полные метаданные файла, включая три временные метки: atime (доступ), mtime (изменение содержимого) и ctime (изменение прав или владельца). Я использую `stat` для выявления таймстомпинга: ctime нельзя подделать через `touch`, и расхождение между mtime и ctime — серьёзный индикатор компрометации».

## ❓ Самопроверка

1. **Как посмотреть все метаданные файла `/etc/sudoers`?**
   👉 `stat /etc/sudoers`
2. **Какую временную метку НЕЛЬЗЯ изменить командой `touch`?**
   👉 `ctime` — время изменения метаданных (прав, владельца). Она обновляется только ядром.
3. **Что означает, если `Change` новее `Modify`?**
   👉 Содержимое файла не меняли, но меняли права доступа или владельца. Для системных файлов это подозрительно.
4. **Чем `stat` удобнее `ls -la` при расследовании?**
   👉 Показывает atime и ctime, которые `ls -la` не выводит.
