# 👤 chown — смена владельца и группы файла

> [!abstract] Суть одной фразой
> `chown` (Change Owner) — это команда для изменения владельца и группы-владельца файлов и каталогов в [[Linux]]. Для специалиста по ИБ это инструмент исправления прав, когда файлы по ошибке принадлежат не тому пользователю, и поиска аномалий (например, системный файл вдруг принадлежит обычному пользователю).

---

## 📌 Базовое использование

> chown пользователь:группа файл

**Сменить только владельца:**
> chown alice file.txt

**Сменить только группу:**
> chown :developers file.txt

**Сменить и владельца, и группу:**
> chown alice:developers file.txt

---

## 🔑 Ключевые опции

- `-R` (recursive) — рекурсивно сменить владельца для папки и всего её содержимого.
- `--from=старый_владелец` — сменить владельца только если текущий владелец совпадает с указанным (защита от ошибок).

> chown -R www-data:www-data /var/www/html

Установит владельца `www-data` и группу `www-data` на всю папку сайта и все вложенные файлы.

> chown --from=root alice file.txt

Сменит владельца на `alice` только если сейчас файл принадлежит `root`. Если файл уже принадлежит другому пользователю — ничего не произойдёт.

---

## 🕵️ Примеры для специалиста по ИБ

**Найти файлы, принадлежащие несуществующему пользователю (после удаления учётной записи):**
> find / -nouser

**Найти файлы без группы:**
> find / -nogroup

**Проверить владельца критичных файлов:**
> ls -la /etc/shadow

Файл должен принадлежать `root:shadow`. Если владелец другой — это аномалия.

**Исправить права после ошибочного `chown` на всю систему (восстановить владельца ключевых папок):**
> chown root:root /etc /bin /sbin /lib

## 🔗 Связи

- [[Linux]] — основная ОС.
- [[chmod]] — изменение прав доступа (часто используется вместе с `chown`).
- [[ls]] — просмотр текущего владельца (`ls -la`).
- [[find]] — поиск файлов по владельцу (`find / -user username`).

## 🧠 Значимость для меня как специалиста по ИБ

- Я знаю, что при аудите всегда проверяю владельцев критичных файлов (`/etc/shadow`, ключи SSH, конфигурации веб-сервера) и исправляю их через `chown`.
- Я понимаю, что если системный файл принадлежит обычному пользователю — это либо ошибка администрирования, либо след атаки.
- Я помню, что `chown -R` на системных папках (`/etc`, `/bin`) может сломать систему, и применяю его осторожно.

## ❓ Самопроверка

1. **Как сменить только группу файла на `admins`?**
   👉 `chown :admins file.txt`
2. **Как рекурсивно установить владельца `www-data` на всю папку сайта?**
   👉 `chown -R www-data:www-data /var/www/html`
3. **Почему смена владельца `/etc/shadow` на обычного пользователя опасна?**
   👉 Этот файл содержит хеши паролей. Если он будет принадлежать не `root`, злоумышленник или пользователь может прочитать и скопировать его для подбора паролей.
