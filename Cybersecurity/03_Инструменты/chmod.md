# 🔐 chmod — изменение прав доступа к файлам и папкам

> [!abstract] Суть одной фразой
> `chmod` (Change Mode) — это команда, которая меняет права доступа к файлам и каталогам в [[Linux]]. Для специалиста по ИБ это один из главных инструментов настройки защиты на уровне файловой системы.

---

## 🔑 Основные флаги

- `-R` (**R**ecursive) — рекурсивно изменить права для папки и всего её содержимого.
- `-v` (**v**erbose) — подробный вывод: показывать, какие изменения были сделаны.
- `-c` (**c**hanges) — показывать только те файлы, чьи права действительно изменились (аналог `-v`, но без лишнего).
- `--reference=файл` — скопировать права с указанного файла, а не задавать их вручную.

## 📌 Два способа задать права

### 1. Цифровой (восьмеричный) режим
Каждая цифра — сумма битов:

| Бит | Значение | Буква |
|---|---|---|
| **4** | Чтение | `r` |
| **2** | Запись | `w` |
| **1** | Выполнение | `x` |

Три цифры — для владельца, группы и остальных:

| Команда | Цифры | Смысл |
|---|---|---|
| `chmod 600 file` | `rw-------` | Только владелец читает и пишет. Стандарт для SSH-ключей. |
| `chmod 644 file` | `rw-r--r--` | Владелец пишет, остальные только читают. Для конфигов. |
| `chmod 755 dir` | `rwxr-xr-x` | Владелец управляет, остальные могут заходить и читать. Для скриптов и папок. |
| `chmod 777 file` | `rwxrwxrwx` | **Катастрофа.** Кому угодно можно всё. Никогда не использовать для критичных файлов. |

### 2. Символьный режим
Удобен, когда нужно добавить или убрать одно право, не меняя остальные.

- `u` — владелец (user), `g` — группа (group), `o` — остальные (others), `a` — все (all).
- `+` добавить, `-` убрать, = установить точно.

> chmod u+x script.sh   # дать владельцу право на выполнение
> chmod o-w file.txt    # запретить запись для остальных
> chmod a=r file.txt    # всем только чтение (сбросить остальные права)

---

## 🔑 Рекурсивное изменение

> chmod -R 755 папка/

Установит права `755` на папку и **на все вложенные файлы и папки**. Осторожно: для файлов внутри папки `755` означает разрешение на выполнение, что нужно не всегда.

## 🧠 Значимость для меня как специалиста по ИБ

- Я знаю, что `chmod 600` — стандарт для закрытых ключей, и всегда проверяю это при аудите.
- Я могу мгновенно оценить права на файл по цифрам (`644` — норма, `777` — повод для немедленного исправления).
- Я помню, что рекурсивное изменение прав (`-R`) требует осторожности: легко случайно дать файлам право на выполнение.

---

## 💬 Ответ на собеседовании (кратко)

> «`chmod` меняет права доступа. Цифровой режим: 4 — чтение, 2 — запись, 1 — выполнение. `600` — только владелец, `644` — конфиги, `755` — скрипты. `777` — полный доступ для всех, недопустимо для критичных файлов. Символьный режим удобен для добавления одного права: `chmod u+x script.sh`».

## ❓ Самопроверка

1. **Что делает команда `chmod 600 private.key`?**
   👉 Даёт владельцу права на чтение и запись, для группы и остальных — никаких прав.
2. **Как добавить право на выполнение только владельцу, не меняя остальные права?**
   👉 `chmod u+x script.sh`
3. **Почему `chmod 777` — это плохо?**
   👉 Любой пользователь системы может читать, изменять и запускать файл. Для ключей и конфигов это означает полную компрометацию.
