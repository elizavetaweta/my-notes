# 🔒 shred — безопасное удаление файлов с перезаписью

> [!abstract] Суть одной фразой
> `shred` — это команда для гарантированного уничтожения файла путём многократной перезаписи его содержимого случайными данными перед удалением. В отличие от [[rm]], который только удаляет запись о файле из [[Файловая система|файловой системы]], `shred` делает восстановление данных практически невозможным.

Для специалиста по ИБ `shred` — это инструмент безопасной очистки конфиденциальных данных перед списанием носителя, утилизации ключей и предотвращения утечек через выброшенные жёсткие диски.

---

## 📌 Базовое использование

**Перезаписать и удалить файл (3 прохода по умолчанию):**

> shred -u secret.txt

- `-u` (**u**nlink) — перезаписать и **удалить** файл после этого, освободив место на диске.

**Только перезаписать, но не удалять:**

> shred secret.txt

Файл останется на диске, но его содержимое будет заменено случайными данными.

**Перезаписать с заданным количеством проходов:**

> shred -n 7 -u secret.txt

- `-n N` (**n**umber) — выполнить N проходов перезаписи (вместо трёх по умолчанию).

---

## 🔑 Ключевые опции

- `-u` (**u**nlink) — после перезаписи удалить файл и освободить место на диске.
- `-n N` (**n**umber) — количество проходов перезаписи (по умолчанию 3).
- `-z` (**z**ero) — последним проходом записать нули, чтобы скрыть факт перезаписи случайными данными.
- `-f` (**f**orce) — принудительно изменить права доступа, если текущие не позволяют перезаписать файл.
- `-v` (**v**erbose) — подробный вывод: показывать прогресс и информацию о каждом шаге.

> shred -v -n 5 -z -u sensitive_data.txt

Выполнит 5 проходов случайными данными, затем один проход нулями (скрывая следы перезаписи), удалит файл и покажет ход работы.

---

## ⚠️ Ограничения и когда `shred` НЕ спасёт

> [!danger] Эта команда эффективна на старых жестких дисках (**HDD**).
> На современных SSD и флешках `shred` может не дать гарантий
> Контроллер SSD может переназначать сектора (wear levelling) и записывать данные в другое физическое место. Из-за этого старые копии могут остаться на чипе. Для SSD рекомендуется использовать **полное шифрование диска** ([[LUKS]], [[VeraCrypt]]) и затем сброс ключа.

> [!danger] На журналируемых файловых системах (ext4, XFS, NTFS)
> Журнал может содержать копии данных. `shred` перезаписывает только сам файл, но не журнал. Гарантированное уничтожение — только шифрование всего раздела.

## 💾 Как надёжно стирать данные на SSD

В отличие от жёстких дисков (HDD), твердотельные накопители (SSD) имеют встроенный контроллер, который распределяет запись по ячейкам для равномерного износа (wear levelling). Из‑за этого команда `shred` не может гарантированно затереть старые копии данных — контроллер может просто перенаправить запись в другие ячейки, оставив исходные нетронутыми. Для надёжного уничтожения информации на SSD применяются другие методы.

### 🔧 ATA Secure Erase (для SATA SSD)

Это аппаратная команда, которая заставляет контроллер диска очистить все ячейки памяти. Выполняется с помощью утилиты `hdparm`.

> sudo hdparm --user-master u --security-set-pass NULL /dev/sda
> sudo hdparm --user-master u --security-erase NULL /dev/sda

- Первая команда устанавливает временный пароль (NULL), без которого Secure Erase не запустится.
- Вторая команда запускает саму процедуру очистки.

> [!warning] Осторожно
> Эта операция полностью и необратимо уничтожает **все** данные на диске. Перед выполнением убедись, что выбрано правильное устройство.

### 🚀 NVMe Format (для NVMe SSD)

Для современных NVMe‑накопителей аналогом Secure Erase является команда `nvme format` из пакета `nvme-cli`.

> sudo nvme format /dev/nvme0n1 --ses=1

- `--ses=1` (Secure Erase Setting) — запускает криптографическое стирание: контроллер уничтожает внутренний ключ шифрования, и все данные мгновенно становятся нечитаемыми.

### 🔐 Полное шифрование диска (LUKS, VeraCrypt)

Самый надёжный и универсальный метод для любых SSD, включая внешние. Логика проста:

1. **Перед** началом работы с конфиденциальными данными весь диск или раздел шифруется (например, с помощью [[LUKS]] или [[VeraCrypt]]).
2. Когда данные нужно уничтожить, достаточно **уничтожить ключ шифрования** (сбросить заголовки LUKS или удалить парольную фразу).
3. Без ключа все данные на диске превращаются в «случайный мусор» — восстановить их невозможно.

> [!note] Почему это эффективно
> На SSD никогда не хранились открытые данные — они всегда были зашифрованы. Уничтожение ключа не требует перезаписи каждой ячейки, обходит ограничения wear levelling и работает мгновенно.



## 🕵️ Сценарии для специалиста по ИБ

### 1. Уничтожение временных ключей после использования

> shred -u session_key.pem

### 2. Очистка диска перед списанием

> shred -v -n 1 /dev/sdb

Один проход случайными данными на всём устройстве (достаточно для большинства случаев). Для гостайны — 3–7 проходов.

### 3. Зачистка файлов после расследования

> find /tmp -type f -exec shred -u {} \;

Уничтожит все файлы в `/tmp`, чтобы нельзя было восстановить временные улики после закрытия дела.

## 🆚 `shred` vs `rm`

| Характеристика | `rm` | `shred` |
|---|---|---|
| **Что делает** | Удаляет запись о файле из файловой системы | Многократно перезаписывает содержимое, затем удаляет |
| **Можно ли восстановить данные** | Да, пока не перезаписаны | Практически невозможно |
| **Когда использовать** | Повседневное удаление | Уничтожение конфиденциальных данных |
| **Опасность** | Низкая | Средняя (перезапись необратима) |

---

## 🧠 Что такое «перезапись» в контексте `shred`

Обычное удаление (`rm`) не стирает данные — оно помечает место на диске как свободное. Сами байты остаются нетронутыми, пока их не затрут новые файлы.

`shred` делает обратное: он **принудительно записывает** поверх старого содержимого случайные данные (а затем, с опцией `-z`, нули). После нескольких проходов исходные байты уже не восстановить даже специальным оборудованием.

**Аналогия с бумагой:**
- `rm` — убрать лист из оглавления, оставив его в стопке.
- `shred` — многократно закрасить лист карандашом и корректором, превратив в мешанину, и только потом выбросить.

## 🔗 Связи

- [[rm]] — обычное удаление.
- [[dd]] — ещё один инструмент для низкоуровневой перезаписи (`dd if=/dev/urandom of=/dev/sdb`).
- [[LUKS]], [[VeraCrypt]] — шифрование диска (более надёжный способ защиты).
- [[Файловая система]] — контекст, в котором работает `shred`.
- [[Linux]] — основная ОС.

1. **Чем `shred` отличается от `rm`?**
   👉 `rm` только удаляет запись о файле, данные остаются на диске. `shred` многократно перезаписывает данные случайными байтами перед удалением.
2. **Почему `shred` может быть неэффективен на SSD?**
   👉 Контроллер SSD может записывать данные в другие физические ячейки из-за wear levelling, и старые копии могут сохраниться.
3. **Как уничтожить файл с 7 проходами и скрыть следы перезаписи?**
   👉 `shred -n 7 -z -u secret.txt`
