# ✳️ Специальные символы в Bash — звёздочка `*` (Wildcard)

> [!abstract] Суть одной фразой
> `*` (звёздочка, wildcard) — это специальный символ в [[Bash]], который означает «любая последовательность символов (включая пустую)». Она используется для поиска файлов по шаблону, фильтрации текста и массовых операций без перечисления каждого имени вручную.

Для специалиста по ИБ `*` — незаменимый инструмент при аудите: быстро найти все конфигурационные файлы, проверить права на группы файлов, выделить логи по дате.

---

## 📌 Как работает `*`

Когда Bash встречает `*` в команде, он **разворачивает** её в список всех файлов и папок, подходящих под шаблон. Это происходит **до** выполнения команды.

Например:
> ls *.txt

Bash превращает `*.txt` в список всех имён, заканчивающихся на `.txt`, и `ls` получает уже готовый список файлов.

Если подходящих файлов нет, Bash передаёт `*` как обычный символ, и команда может выдать ошибку.

---

## 🔑 Типичные шаблоны

| Шаблон | Что ищет | Пример |
|---|---|---|
| `*.conf` | Все файлы, заканчивающиеся на `.conf` | `ls /etc/*.conf` |
| `*log*` | Все файлы, в имени которых есть `log` | `ls /var/log/*log*` |
| `file_?.txt` | `file_1.txt`, `file_a.txt`, но не `file_12.txt`. `?` — ровно один символ | `ls file_?.txt` |
| `[abc]*.log` | Все `.log`-файлы, имя которых начинается с `a`, `b` или `c` | `ls [abc]*.log` |
| `{*.conf,*.cfg}` | Все файлы с расширениями `.conf` и `.cfg` (фигурное расширение) | `ls /etc/{*.conf,*.cfg}` |

> [!note] Звёздочка не заходит в подпапки
> `ls /etc/*.conf` покажет только файлы, лежащие **прямо** в `/etc`. Чтобы искать рекурсивно (включая все подпапки), нужно использовать `find`, а не полагаться на `*`.

---

## 🔧 Когда `*` не срабатывает и что делать

- **Пробелы в именах.** `*` разворачивается в список аргументов, разделённых пробелами. Файл `Мои документы.txt` будет воспринят как два отдельных аргумента. Решение: всегда брать шаблон в двойные кавычки, если результат подстановки передаётся в другую команду.

- **Слишком много файлов.** Bash имеет ограничение на длину команды. Если шаблону соответствует слишком много файлов, команда может не выполниться. В таких случаях используй `find ... -exec` вместо `*`.

- **Нестандартные расширения.** `*.conf` не найдёт файлы `.conf.bak` или `.conf.old`. Для этого подходит `find` с тестом `-name`, где `*` работает глубже.

---

## 🕵️ Примеры для специалиста по ИБ

**Найти все конфигурационные файлы в `/etc`:**
> ls /etc/*.conf

**Проверить права на все скрипты в домашней папке:**
> ls -la ~/*.sh

**Архивировать все логи за день:**
> tar -czf logs_$(date +%Y%m%d).tar.gz /var/log/*.log

**Удалить все временные файлы (осторожно!):**
> rm -rf /tmp/*

## ❓ Самопроверка

1. **Как найти все файлы с расширением `.log` в текущей папке?**
   👉 `ls *.log`
2. **Почему `rm *` может быть опасен?**
   👉 Удалит все файлы в текущей папке без подтверждения.
3. **Что делать, если `*` не захватывает файлы в подпапках?**
   👉 Использовать `find` с опцией `-name`.
