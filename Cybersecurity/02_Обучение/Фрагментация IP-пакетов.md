# 🧩 Фрагментация IP-пакетов

> [!abstract] Суть одной фразой
> Фрагментация — это процесс разбиения IP-пакета, превышающего [[MTU (Maximum Transmission Unit)]], на несколько более мелких фрагментов, каждый из которых передаётся как самостоятельный IP-пакет. Сборка (реассемблирование) происходит только на приёмной стороне. Фрагментация ухудшает производительность и может использоваться в атаках для обхода систем обнаружения вторжений.

---

## 📌 Когда происходит фрагментация

1. Отправитель создаёт пакет, который больше MTU исходящего интерфейса.
2. Исходный пакет разбивается на фрагменты, каждый со своим IP-заголовком.
3. Все фрагменты помечаются одинаковым идентификатором пакета (Identification), а в поле Fragment Offset указывается смещение данных фрагмента внутри исходного пакета.
4. Получатель собирает исходный пакет из фрагментов. Если хотя бы один фрагмент потерян, весь пакет считается утерянным.

## ⚔️ Значимость для ИБ

- **Обход IDS/IPS.** Атакующий может намеренно фрагментировать вредоносный пакет так, что сигнатуры IDS не сработают на отдельных фрагментах.
- **DoS-атаки.** Отправка большого количества фрагментов с неполным набором переполняет буферы сборки на приёмной стороне.

---

## 🔗 Связи

- [[MTU (Maximum Transmission Unit)]] — причина фрагментации.
- [[Пакет (сетевой)]] — объект, который фрагментируется.
- [[ICMP (Internet Control Message Protocol)]] — возвращает ошибку «нужна фрагментация», если фрагментация запрещена флагом DF.

## 💬 Ответ на собеседовании (кратко)

> «Фрагментация IP разбивает пакет, больший MTU, на несколько частей. Сборка происходит только на приёмной стороне. Это замедляет передачу и может использоваться злоумышленниками для обхода IDS. Я избегаю фрагментации, настраивая MTU, и проверяю сеть через `ping -M do`».

## ❓ Самопроверка

1. **Где собираются фрагменты обратно?** 👉 Только на приёмном хосте.
2. **Как запретить фрагментацию для пакета?** 👉 Установить флаг DF (Don't Fragment) в IP-заголовке.
