# 📡 Типы сетевых коммуникаций: Unicast, Multicast, Broadcast

> [!abstract] Суть одной фразой
> В зависимости от количества получателей сетевые коммуникации делятся на три типа: **Unicast** (адресная передача одному получателю), **Multicast** (групповая передача нескольким получателям одновременно) и **Broadcast** (широковещательная передача всем устройствам в сети). Понимание этих режимов необходимо для анализа трафика, настройки VLAN и обнаружения атак (например, штормовых broadcast-атак).

---

## 📌 Unicast — «один к одному»

Unicast подразумевает передачу пакета от одного отправителя **ровно одному** получателю. Каждый пакет адресован конкретному [[IP-адрес]]у или [[MAC-адрес]]у.

- Используется для большинства пользовательских протоколов: HTTP, SSH, FTP.
- Коммутатор пересылает такой кадр только в порт, где находится получатель (если знает его MAC-адрес).
- Не создаёт лишней нагрузки на другие узлы сети.

## 📢 Broadcast — «один ко всем»

Broadcast означает передачу пакета, который получают **все** устройства в данном широковещательном домене (например, в одной VLAN или локальной сети без VLAN). На канальном уровне используется специальный MAC-адрес `FF:FF:FF:FF:FF:FF`, на сетевом — ограниченный broadcast-адрес `255.255.255.255`.

- Используется протоколами ARP и DHCP на начальном этапе, когда отправитель не знает точного адреса получателя.
- Коммутатор рассылает такой кадр во все порты.
- Избыточный broadcast-трафик может вызывать широковещательный шторм, снижающий производительность сети.

## 🎯 Multicast — «один ко многим»

Multicast позволяет отправить один пакет сразу **нескольким получателям**, которые явно подписались на соответствующую группу. Используются специальные диапазоны IP-адресов (224.0.0.0–239.255.255.255 для IPv4) и соответствующие им MAC-адреса.

- Применяется для стриминга видео, IPTV, обновлений по сети, финансовых котировок.
- Позволяет экономить пропускную способность: отправитель посылает один пакет, а сеть тиражирует его только на те порты, где есть подписчики (при поддержке IGMP).
- В отличие от broadcast, не нагружает устройства, которым этот трафик не нужен.

## 🔗 Связи

- [[Пакет (сетевой)]], [[Кадр (Frame)]] — в заголовках указывается тип адресации.
- [[IP-адрес]], [[MAC-адрес]] — адреса, используемые в разных типах коммуникаций.
- [[ARP (Address Resolution Protocol)]]], [[DHCP (Dynamic Host Configuration Protocol)]] — протоколы, активно использующие broadcast.
- [[VLAN]] — ограничивает распространение broadcast-трафика.

## ❓ Самопроверка

1. **Какой тип передачи использует DHCP-клиент для обнаружения сервера?** 👉 Broadcast (широковещательный запрос).
2. **Чем Multicast принципиально лучше Broadcast для стриминга?** 👉 Пакет получают только заинтересованные подписчики, не нагружая остальных.
