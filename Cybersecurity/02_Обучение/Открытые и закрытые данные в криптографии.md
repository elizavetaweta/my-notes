## 🔏 Открытые и закрытые данные в криптографии

В зависимости от контекста, эти термины описывают либо состояние самой информации, либо элементы криптографического ключа.

---

### 1. По состоянию информации (До и После шифрования)

Это базовое разделение данных, которые передаются по сети или хранятся на диске.

*   **Открытые данные (Plaintext / Чистый текст):**
    *   Это исходная информация в её первоначальном, читаемом виде. Ее может прочесть любой человек или перехватить злоумышленник в незащищенной сети.
*   **Закрытые / Зашифрованные данные (Ciphertext / Криптограмма):**
    *   Это результат математического преобразования открытых данных с помощью алгоритма шифрования. 
    *   Они выглядят как случайный набор байт или хаотичная текстовая строка. Без специального ключа извлечь из них смысл невозможно.


---

### 2. По типу ключей (В контексте асимметричного шифрования RSA)

В асимметричной криптографии (которую вы использовали) данные делятся на основе того, какими **ключами** они обрабатываются. Безопасность строится на математической связи между двумя ключами:

*   **Открытые данные ключа (Public Data / Публичный ключ):**
    *   Это ключ (`public.key`), который доступен абсолютно всем. Его не нужно прятать.
    *   *Зачем нужен:* С его помощью любое мобильное устройство или пользователь может **зашифровать** данные для сервера. Открытый ключ работает как «навесной замок»: закрыть его может любой, у кого он есть, но открыть обратно — нельзя.
*   **Закрытые данные ключа (Private Data / Приватный / Секретный ключ):**
    *   Это ключ (`private.key`), который хранится в строжайшем секрете и известен только одной стороне (владельцу сервера).
    *   *Зачем нужен:* С его помощью сервер **расшифровывает** полученные криптограммы. Если закрытый ключ попадет к злоумышленникам, вся защита мгновенно рухнет, так как они смогут читать любой перехваченный трафик.

---

> [!💡 Важное правило]
> При шифровании данных карты вы использовали **открытый (публичный) ключ** для создания **закрытых (зашифрованных) данных**. А сервер с помощью своих **закрытых (секретных) данных ключа** превратит их обратно в **открытый (читаемый) текст**.
