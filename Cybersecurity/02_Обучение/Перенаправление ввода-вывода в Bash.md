# 🔄 Перенаправление ввода-вывода в Bash (`>`, `>>`, `<`, `|`)

> [!abstract] Суть одной фразой
> Перенаправления позволяют командам [[Bash]] читать данные не с клавиатуры, а из файла (`<`), и выводить результат не на экран, а в файл (`>`, `>>`) или напрямую в другую команду (`|`). Для специалиста по ИБ это основа автоматизации: сбор логов, фильтрация, создание отчётов.

---

## 📌 Четыре главных символа

| Символ | Название                            | Что делает                                                   | Простая аналогия            |
| ------ | ----------------------------------- | ------------------------------------------------------------ | --------------------------- |
| `>`    | Перенаправление вывода (перезапись) | Сохраняет вывод команды в файл, **стирая** старое содержимое | «Сохранить как новый файл»  |
| `>>`   | Перенаправление вывода (дозапись)   | Добавляет вывод команды **в конец** файла                    | «Дописать в конец блокнота» |
| `<`    | Перенаправление ввода               | Подаёт содержимое файла на вход команде                      | «Скормить файл команде»     |
| \|     | Конвейер (pipe)                     | Направляет вывод одной команды на вход другой                | «Соединить две трубы»       |

---

## 🔍 Подробный разбор

### `>` — запись в файл (с перезаписью)

> echo "Попытка взлома" > alert.log

Создаст файл `alert.log` и запишет в него строку. Если файл уже существовал — его содержимое будет **уничтожено** и заменено новым.

**Когда использовать:** сохранить результат сканирования, создать новый лог, перезаписать конфигурацию.

**Опасно:** `>` молча перезаписывает файлы. Не используй с важными данными, если не уверена.

---

### `>>` — дозапись в конец файла

> echo "Ещё одна попытка" >> alert.log

Добавит строку в конец `alert.log`, не трогая то, что уже было записано.

**Когда использовать:** вести журнал событий, дописывать результаты повторных проверок, накапливать вывод cron-задач.

> [!example] Пример для аудита
> `find / -type f -perm 0777 >> insecure_files.log`  
> Допишет найденные «дырявые» файлы в журнал, не стирая предыдущие находки.

---

### `<` — чтение из файла

> cat < /etc/passwd

Команда `cat` получит содержимое `/etc/passwd` как будто ты ввела его с клавиатуры.

### 🔍 `cat /etc/passwd` vs `cat < /etc/passwd` — в чём разница

Обе команды выводят содержимое файла, но работают по-разному:

- `cat /etc/passwd` — `cat` получает имя файла как аргумент и **сама его открывает**.
- `cat < /etc/passwd` — оболочка открывает файл и **перенаправляет его содержимое** на стандартный ввод `cat`. Команда `cat` не знает имени файла — она просто читает stdin.

> [!note] Когда это важно
> Некоторые утилиты (например, `tr`, `sort`) не принимают имена файлов как аргументы и работают только со стандартным вводом. Для них `tr 'a-z' 'A-Z' < file` — единственный способ обработать файл.

Для специалиста по ИБ понимание разницы помогает анализировать скрипты и логи: не всякая команда, читающая файл, делает это «осознанно».

**Когда использовать `<`:** подать файл на вход программе, которая обычно ждёт ввода от пользователя (например, `sort < unsorted.txt`).

**Не путай с `>`:**  
- `>` — вывод команды → в файл.  
- `<` — файл → на вход команде.

---

### `|` — конвейер (pipe)

> ps aux | grep sshd

Вывод `ps aux` (список всех процессов) передаётся **напрямую** команде `grep sshd`. На экран попадёт только строка с `sshd`.

**Когда использовать:** фильтрация, сортировка, комбинирование команд. Это «клей», соединяющий простые утилиты в мощные цепочки.

> [!example] Пример для расследования
> `cat /var/log/auth.log | grep "Failed password" | awk '{print $11}' | sort | uniq -c | sort -rn | head`  
> Покажет топ IP-адресов, с которых пытались подобрать пароль.

---

## 🧠 Как запомнить разницу между `|` и `>`

- **`|` (pipe)** — данные идут **от команды к команде**, не сохраняясь на диск. Живой поток.
- **`>` (в файл)** — данные **сохраняются** на диск. Мёртвый слепок.
- **`>>`** — то же, что `>`, но без удаления старого содержимого.
- **`<`** — данные **читаются** из файла, а не с клавиатуры.


## 🕳️ `/dev/null` и подавление ошибок (`2>`)

В Linux у каждой программы есть два стандартных потока вывода:

| Дескриптор | Название | Что это |
|---|---|---|
| `1` (stdout) | Стандартный вывод | Обычный результат работы команды |
| `2` (stderr) | Стандартный вывод ошибок | Сообщения об ошибках и предупреждения |

- `команда > файл` перенаправляет **только** stdout (дескриптор 1).
- `команда 2> файл` перенаправляет **только** stderr (дескриптор 2).

`/dev/null` — это специальное устройство-«чёрная дыра». Всё, что в него записано, бесследно исчезает.

> find / 2>/dev/null | grep shadow

- `2>/dev/null` — все ошибки `Permission denied` от `find` летят в «чёрную дыру».
- На экран попадает только чистый список найденных файлов.

**Также можно перенаправить stdout и stderr в один файл:**
> команда > общий_лог.txt 2>&1

## ❓ Самопроверка

1. **Что делает команда `echo test > file.txt`?**  
   👉 Создаст `file.txt` и запишет в него `test`. Если файл был, он будет перезаписан.
2. **Чем `>>` отличается от `>`?**  
   👉 `>` стирает файл перед записью, `>>` добавляет строку в конец.
3. **Как передать вывод одной команды на вход другой?**  
   👉 Через `|` (pipe): `команда1 | команда2`.
4. **Что такое `<`?**  
   👉 Это перенаправление ввода: команда читает данные из файла, а не с клавиатуры.
