# 🔗 Логические операторы и условия в Bash

> [!abstract] Суть одной фразой
> Логические операторы в [[Bash]] управляют порядком выполнения команд (`&&`, `||`, `;`, `&`) и формируют условия в скриптах (`!`, `-eq`, `-f`, `=`, `!=` и десятки других). Для специалиста по ИБ это фундамент безопасной автоматизации: проверка файлов, прав, процессов, кодов возврата и ветвление логики сценариев.

---

## 📌 Два контекста использования

В Bash операторы работают по‑разному в зависимости от того, где используются:

- **Цепочки команд в терминале или скрипте:** `&&`, `||`, `;`, `&` связывают команды между собой.
- **Условные выражения внутри `[ ... ]` или `[[ ... ]]`:** здесь живут операторы сравнения чисел, строк, проверки файлов и логические `!`, `&&`, `||`.

---

## 🔹 1. Цепочки команд — `&&`, `||`, `;`, `&`

Используются для связывания нескольких команд в одной строке.

| Оператор   | Логика                                                                            | Пример                                                       |
| ---------- | --------------------------------------------------------------------------------- | ------------------------------------------------------------ |
| `&&` (И)   | Выполнить вторую команду, **только если** первая завершилась успешно (код 0)      | `mkdir /secure && chmod 700 /secure`                         |
| \|\| (ИЛИ) | Выполнить вторую команду, **только если** первая завершилась с ошибкой (код не 0) | `systemctl is-active fail2ban \|\| systemctl start fail2ban` |
| `;`        | Выполнить команды последовательно **всегда**, независимо от результата            | `cd /tmp; rm -rf *`                                          |
| `&`        | Запустить первую команду **в фоне** и сразу перейти ко второй                     | `tar -czf backup.tar.gz /data &`                             |

> [!danger] Осторожно с `;`
> `cd /tmp; rm -rf *` удалит файлы, даже если `cd` провалился (останется в текущей папке). `cd /tmp && rm -rf *` безопаснее — удаление выполнится только при успешном переходе.

> [!note] Как Bash понимает «успех»
> Каждая команда возвращает **код возврата** (exit code): `0` — успех, не `0` — ошибка. Посмотреть код последней команды: `echo $?`.

---

## 🔹 2. Условные выражения: `[ ]` vs `[[ ]]`

Внутри скобок записываются условия, которые возвращают истину (0) или ложь (не 0).

- `[ condition ]` — традиционный POSIX-совместимый синтаксис (работает в `sh`). Требует пробелов вокруг скобок. Операторы `&&` и `||` внутри **не** поддерживаются (нужно использовать `-a` и `-o`).
- `[[ condition ]]` — расширенный синтаксис Bash (и Zsh). Поддерживает `&&`, `||`, =~ (регулярные выражения), не требует экранирования `<` и `>`. **Рекомендуется для Bash-скриптов.**

```bash
# Правильно (с пробелами!)
if [[ -f /etc/shadow ]]; then echo "Файл существует"; fi
```

## 🔹 3. Логические операторы внутри условий

| Оператор | Значение                   | Пример                                      |
| -------- | -------------------------- | ------------------------------------------- |
| !        | НЕ (отрицание)             | [[ ! -f /etc/shadow ]] && echo "Файла нет!" |
| &&       | И (оба условия истинны)    | [[ -f /key && -r /key ]]                    |
| \|\|     | ИЛИ (хотя бы одно истинно) | [[ $1 == "start" \|\| $1 == "stop" ]]       |
 >[!warning] Устаревшие -a и -o
Внутри [ ] можно использовать -a (AND) и -o (OR), но это не рекомендуется: они могут быть двусмысленными. Лучше всегда [[ ]] и явные &&/||.

## 🔹 6. Файловые тесты (проверка атрибутов файлов)

Ты приходишь в библиотеку и задаёшь вопросы о конкретной книге (файле или папке). Bash «отвечает» ДА (истина) или НЕТ (ложь).

Самые востребованные в ИБ:

| Тест   | Истина, если                                  | Пример использования                            |
| ------ | --------------------------------------------- | ----------------------------------------------- |
| -f<br> | это обычный файл                              | [[ -f /etc/shadow ]]                            |
| -d     | это директория                                | [[ -d /var/log ]]                               |
| -e     | файл/папка существует (любой тип)             | [[ -e /tmp/backdoor ]]                          |
| -r     | файл читаемый                                 | `[[ -r /etc/shadow ]]` — критично, если не root |
| -w     | файл доступен для записи                      | `[[ -w /etc/sudoers ]]` — признак компрометации |
| -x     | файл исполняемый                              | [[ -x /tmp/suspicious ]]                        |
| -s     | файл не пустой (size > 0)                     | [[ -s /var/log/auth.log ]]                      |
| -O     | владелец файла — текущий пользователь         | [[ -O ~/.ssh/id_rsa ]]                          |
| -G     | группа файла совпадает с группой пользователя | [[ -G /etc/shadow ]]                            |
| -N     | файл изменялся с момента последнего чтения    | [[ -N /etc/passwd ]]                            |
|        |                                               |                                                 |
>[!example] Типичная проверка для аудита  
`if [[ -f /etc/shadow && -r /etc/shadow && ! -O /etc/shadow ]]; then echo "ТРЕВОГА: shadow читается, но не принадлежит root"; fi`

## ❓ Самопроверка
Как безопасно удалить папку, только если удалось в неё перейти?
👉 cd /tmp/mydir && rm -rf *

Как проверить, что файл /etc/shadow существует и доступен для чтения?
👉 [[ -f /etc/shadow && -r /etc/shadow ]]

Что делает [[ -w /etc/sudoers ]] и почему это опасно?
👉 Проверяет, доступен ли файл sudoers для записи. Если да — злоумышленник мог модифицировать его и повысить привилегии.

Чем [[ ]] лучше [ ]?
👉 Поддерживает &&, ||, =~ (регулярки), не нужно экранировать < и >.
