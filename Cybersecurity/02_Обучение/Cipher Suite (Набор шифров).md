# 🔐 Cipher Suite (Набор шифров)

> [!abstract] Суть одной фразой
> Cipher Suite — это именованный набор криптографических алгоритмов, определяющих параметры защиты соединения в протоколах [[TLS]] и [[SSL]]. Набор фиксирует алгоритм обмена ключами, аутентификации сервера, симметричного шифрования и хеширования/имитовставки (MAC). Клиент и сервер согласуют конкретный набор во время рукопожатия.

Для специалиста по ИБ аудит Cipher Suites — обязательная часть проверки защищённости веб-серверов, почтовых сервисов и VPN-шлюзов. Слабый набор (например, с RC4 или SHA-1) делает шифрование бесполезным.

---

## 📌 Структура Cipher Suite (до TLS 1.2)

До TLS 1.3 название набора кодировало четыре компонента:

`TLS_ECDHE_RSA_WITH_AES_128_GCM_SHA256`

| Компонент | Значение в примере | Что делает |
|---|---|---|
| **Обмен ключами** | `ECDHE` | Эфемерный Диффи‑Хеллман на эллиптической кривой — безопасно вырабатывает сессионный ключ |
| **Аутентификация** | `RSA` | Сервер подтверждает свою подлинность сертификатом [[RSA]] |
| **Шифрование** | `AES_128_GCM` | Симметричное шифрование данных: алгоритм [[AES]] с ключом 128 бит в режиме [[Режимы блочного шифрования|GCM]] |
| **Хеширование (MAC)** | `SHA256` | [[SHA‑2 (SHA‑256 и SHA‑512)|SHA‑256]] используется в HMAC для имитозащиты и в функции псевдослучайного вывода (PRF) |

---

## 🔑 Cipher Suites в TLS 1.3

В [[TLS]] 1.3 структура упрощена: обмен ключами и аутентификация вынесены из названия, остаётся только связка «шифрование + хеш».

`TLS_AES_256_GCM_SHA384`

- `AES_256_GCM` — симметричное шифрование с аутентификацией (AEAD).
- `SHA384` — хеш для HMAC и PRF.
- Обмен ключами всегда эфемерный (ECDHE или DHE) и обеспечивает **Perfect Forward Secrecy (PFS)** — компрометация долговременного ключа не раскрывает прошлые сессии.
- Аутентификация определяется сертификатом (RSA, ECDSA и др.).

---

## ✅ Безопасные и ❌ небезопасные алгоритмы в Cipher Suites

| Компонент | ✅ Рекомендуется | ❌ Устарело / запрещено |
|---|---|---|
| **Обмен ключами** | ECDHE, DHE (с PFS) | Статический RSA, DH |
| **Аутентификация** | RSA (2048+), ECDSA | RSA (< 2048) |
| **Шифрование** | AES‑GCM, ChaCha20‑Poly1305 | AES‑CBC, RC4, 3DES |
| **Хеш / MAC** | SHA‑256, SHA‑384 | SHA‑1, MD5 |

> [!danger] Слабый Cipher Suite
> `TLS_RSA_WITH_AES_128_CBC_SHA` — статический RSA (нет PFS), CBC (нет встроенной имитозащиты), SHA‑1 (коллизии). Такой набор должен быть отключён.

## 🕵️ Инструменты для аудита Cipher Suites

Ниже приведены основные утилиты с пояснением ключевых флагов, которые помогают быстро оценить перечень поддерживаемых наборов.

- **nmap** – сканирование с использованием скрипта NSE:
  ```bash
  nmap --script ssl-enum-ciphers -p 443 target.com
  ```
  - `--script` (**script**) — запустить скрипт NSE.
  - `ssl-enum-ciphers` — скрипт, перечисляющий поддерживаемые Cipher Suites.
  - `-p` (**p**ort) — указать порт (443 для HTTPS).

- **sslscan** – специализированный сканер SSL/TLS:
  ```bash
  sslscan --tlsall target.com:443
  ```
  - `--tlsall` (**TLS all**) — проверить все доступные версии TLS.

- **testssl.sh** – мощный bash-скрипт для всестороннего анализа:
  ```bash
  testssl.sh https://target.com
  ```
  (без дополнительных флагов выводит подробный отчёт о поддерживаемых протоколах и наборах)

- **OpenSSL** – точечная проверка под рукой:
  ```bash
  openssl s_client -connect target.com:443 -tls1_2
  ```
  - `-connect` — подключиться к `хост:порт`.
  - `-tls1_2` (**TLS 1.2**) — явно запросить соединение по TLS 1.2, чтобы увидеть, какой набор выбран.
  - Для проверки TLS 1.3 используйте `-tls1_3`.

В выводе обращайте внимание на строку `Cipher`, где указан согласованный набор, и на список `Ciphers` в подзаголовках скриптовых отчётов.

## ❓ Самопроверка

1. **Из каких четырёх компонентов состоит Cipher Suite в TLS 1.2?** 👉 Обмен ключами, аутентификация, шифрование, хеширование.
2. **Почему статический RSA для обмена ключами считается небезопасным?** 👉 Не обеспечивает Perfect Forward Secrecy (PFS): компрометация ключа сервера раскрывает все прошлые сессии.
3. **Какой режим шифрования рекомендуется вместо CBC?** 👉 GCM — он обеспечивает аутентифицированное шифрование (AEAD).
