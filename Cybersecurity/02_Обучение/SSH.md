# 🔐 SSH (Secure Shell)

> [!abstract] Суть одной фразой
> SSH — это криптографический сетевой протокол, предназначенный для безопасного удалённого управления серверами и передачи файлов. Он создаёт зашифрованный туннель между клиентом и сервером, заменяя устаревшие незащищённые протоколы вроде Telnet и FTP. Для специалиста по ИБ SSH — это основной способ администрирования Linux-систем и ключевой объект аудита безопасности.

SSH обеспечивает конфиденциальность (трафик зашифрован), целостность (данные нельзя незаметно изменить) и аутентификацию (обе стороны подтверждают свою подлинность).

---

## 📌 Зачем SSH, если есть Telnet и FTP

До появления SSH администраторы использовали **Telnet** для удалённого управления и **FTP** для передачи файлов. Оба протокола передают данные, включая логины и пароли, **в открытом виде**. Любой, кто перехватит трафик, увидит учётные данные.

SSH решил эту проблему, добавив сквозное шифрование. Сегодня использование Telnet или FTP в production-среде считается критической уязвимостью.

---

## 🔑 Как работает SSH (клиент-сервер)

SSH работает по классической модели [[Клиент (Client)|клиент-сервер]]:

- **SSH-сервер** (демон `sshd`) слушает порт **22/TCP** и ждёт входящих подключений.
- **SSH-клиент** (команда `ssh`) инициирует соединение.

При первом подключении клиент получает и сохраняет **отпечаток публичного ключа сервера**. При последующих подключениях клиент сверяет отпечаток с сохранённым — это защищает от атаки Man-in-the-Middle (MITM).

> ssh user@192.168.1.10

После установки защищённого канала происходит аутентификация пользователя — по паролю или, что гораздо безопаснее, по ключевой паре (закрытый + открытый ключ).

---

## 🔧 Основные команды

> ssh user@remote_host                   # подключиться к серверу
> ssh -p 2222 user@remote_host           # подключиться на нестандартный порт
> ssh -i ~/.ssh/id_rsa user@remote_host  # подключиться с указанием закрытого ключа
> scp file.txt user@remote_host:/tmp/    # копировать файл через SSH
> ssh-keygen -t ed25519                  # сгенерировать ключевую пару (Ed25519)

## 🕵️ Значимость для ИБ

- **Аудит SSH-сервера:** я всегда проверяю, запрещён ли вход по паролю (`PasswordAuthentication no`), отключён ли прямой доступ для root (`PermitRootLogin no`) и используется ли только публичный ключ.
- **Анализ логов:** файл `/var/log/auth.log` (или `journalctl -u sshd`) содержит все попытки подключения. Я ищу `Failed password for root` — классический признак брутфорс-атаки.
- **Отпечатки ключей:** предупреждение `WARNING: REMOTE HOST IDENTIFICATION HAS CHANGED!` — сигнал возможной MITM-атаки или легитимной смены ключа сервера. Я обязана проверить причину, прежде чем продолжать.
- **SSH-туннелирование:** SSH умеет пробрасывать порты (`-L`, `-R`, `-D`). Это полезно для безопасного доступа к внутренним сервисам, но может использоваться злоумышленниками для обхода файрволов и эксфильтрации данных.

## 🔗 Связи

- [[Протоколы транспортного уровня TCP и UDP]] — SSH работает поверх TCP (порт 22).
- [[Порт (сетевой)]] — стандартный порт 22.
- [[Аутентификация]] — по паролю или ключу.
- [[Симметричное шифрование]], [[Асимметричное шифрование]] — SSH использует оба для обмена ключами и шифрования трафика.
- [[SCP]], [[SFTP]] — передача файлов поверх SSH.
- [[Fail2Ban]] — инструмент для блокировки IP после нескольких неудачных попыток SSH.

## ❓ Самопроверка

1. **На каком порту работает SSH по умолчанию?** 👉 22/TCP.
2. **Почему Telnet не используют в современных системах?** 👉 Передаёт логины и пароли в открытом виде.
3. **Что означает предупреждение о смене ключа сервера?** 👉 Возможна MITM-атака, либо сервер легитимно сменил ключ. Нужно обязательно проверить причину.
