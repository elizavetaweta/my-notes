# 🏷️ Адресация в сетях

> [!abstract] Суть одной фразой
> Адресация — это способ идентификации устройств и приложений в сети на разных уровнях модели [[Модель OSI  (Open Systems Interconnection)|OSI]]. Без адресации пакет никогда не дойдёт до цели. На каждом уровне используется свой тип адреса: [[MAC-адрес]] на канальном, [[IP-адрес]] на сетевом, [[Порт (сетевой)|порт]] на транспортном. Вместе они работают как трехуровневая система навигации: от конкретной квартиры (приложения) до почтового отделения (сети).

Для специалиста по ИБ адресация — это основа для фильтрации трафика (ACL, [[iptables]]), выявления аномалий (подмена адресов) и анализа логов. Зная, какой адрес на каком уровне используется, ты точно определяешь, где именно произошла атака и на каком уровне её блокировать.

---

## 📌 Три уровня адресации

При передаче данных по сети используется три типа адресов, каждый из которых «живёт» на своём уровне:

| Уровень OSI | Тип адреса | Пример | Кто его использует | Для чего |
|---|---|---|---|---|
| **L2 – Канальный** | [[MAC-адрес]] | `08:00:27:ab:cd:ef` | Коммутаторы, точки доступа | Доставка кадра конкретному устройству в локальной сети |
| **L3 – Сетевой** | [[IP-адрес]] | `192.168.1.10` | Маршрутизаторы, хосты | Определение подсети и маршрутизация пакетов между сетями |
| **L4 – Транспортный** | [[Порт (сетевой)|Порт]] | `443` (HTTPS), `22` (SSH) | Операционная система | Доставка данных конкретному приложению или службе |

Эти три адреса добавляются последовательно в процессе [[Инкапсуляция (сетевая)|инкапсуляции]], и каждый следующий уровень «заворачивает» данные предыдущего в свой конверт с новым адресом.

---

## 🔍 Как адреса работают вместе (на примере HTTPS-запроса)

Когда ты открываешь сайт `https://ya.ru`, происходит следующее:

1. **Прикладной уровень (L7):** браузер формирует HTTP-запрос.
2. **Транспортный уровень (L4):** к данным добавляется **порт** назначения `443` (HTTPS) и порт отправителя (например, `54321`). Теперь понятно, какому приложению на сервере предназначены данные.
3. **Сетевой уровень (L3):** к сегменту добавляется **IP-адрес** сервера `ya.ru` (например, `87.250.250.242`) и твой IP-адрес. Теперь пакет может пройти через множество маршрутизаторов.
4. **Канальный уровень (L2):** перед отправкой пакет упаковывается в кадр с **MAC-адресом** шлюза по умолчанию (или конечного устройства, если оно в той же подсети). Теперь кадр может быть передан физически.

На приёмной стороне всё происходит в обратном порядке — декапсуляция.

## 🎯 Сравнение адресов

| Характеристика | MAC-адрес | IP-адрес | Порт |
|---|---|---|---|
| **Уровень OSI** | L2 (Канальный) | L3 (Сетевой) | L4 (Транспортный) |
| **Кто назначает** | Производитель оборудования | Администратор сети или [[DHCP (Dynamic Host Configuration Protocol)|DHCP]]-сервер | Операционная система / приложение |
| **Уникальность** | Глобально уникальный | Уникален в пределах сети | Уникален в пределах хоста |
| **Изменяемость** | Можно подменить программно | Может меняться (динамический IP) | Назначается динамически при запуске службы |
| **Формат** | 6 байт в hex (XX:XX:XX:XX:XX:XX) | 4 байта (IPv4) или 16 байт (IPv6) | Число от 0 до 65535 |
| **Пример** | `08:00:27:ab:cd:ef` | `192.168.1.10` | `443` |

## 🛡️ Значимость для специалиста по ИБ

- Я понимаю, что фильтрация трафика работает на каждом уровне адресации: на L2 — по MAC (Port Security), на L3 — по IP ([[iptables]], ACL), на L4 — по портам ([[iptables]], файрвол).
- Подмена адреса (spoofing) возможна на любом уровне: ARP-spoofing (подмена MAC), IP-spoofing, подмена порта. Я знаю, какие меры противодействия применять на каждом уровне.
- При анализе логов и трафика я определяю, какой адрес использовался, и могу восстановить полный маршрут пакета и идентифицировать источник атаки.

## 🔗 Связи

- [[MAC-адрес]], [[IP-адрес]], [[Порт (сетевой)]] — три составляющих адресации.
- [[Инкапсуляция (сетевая)]] — процесс, при котором адреса добавляются к данным.
- [[Модель OSI (Open Systems Interconnection)]] — уровни, на которых работают адреса.
- [[ARP (Address Resolution Protocol)]] — протокол, связывающий IP и MAC.
- [[DHCP (Dynamic Host Configuration Protocol)]] — автоматическое назначение IP-адресов.
- [[iptables]] — фильтрация по IP и портам.

Я понимаю, как эти адреса работают вместе при инкапсуляции, и использую их для фильтрации трафика и расследования инцидентов».

## ❓ Самопроверка

1. **Какой адрес используется для доставки данных внутри локальной сети?** 👉 MAC-адрес.
2. **Какой адрес добавляется к пакету на сетевом уровне?** 👉 IP-адрес.
3. **Почему одного IP-адреса недостаточно для доставки данных?** 👉 Потому что на одном хосте работает множество приложений; порт уточняет, какому именно приложению предназначены данные.
