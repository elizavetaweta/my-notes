# 🚪 Порт (сетевой)

> [!abstract] Суть одной фразой
> Порт — это числовой идентификатор (от 0 до 65535), по которому операционная система понимает, какому именно приложению отдать входящий пакет. IP-адрес доставляет трафик до устройства, а порт — до конкретного процесса на нем. Без этой простой схемы веб-сервер, почтовый демон и база данных на одном хосте не смогли бы работать одновременно.
> Для специалиста по ИБ каждый открытый порт — потенциальная дверь для атаки.

---

## 🔹 Как это работает

Если IP-адрес — адрес многоквартирного дома, то порт — номер квартиры. Пакет приходит на «дом» (IP), а «квартира» (порт) указывает, какое приложение должно получить данные. На транспортном уровне ОС мультиплексирует соединения именно по паре **IP-адрес : порт**, образуя **сокет**.

Таким образом, комбинация `IP:Port` однозначно идентифицирует сетевую конечную точку на хосте, а пара `(локальный сокет, удалённый сокет)` — конкретное соединение.

В операционной системе у каждого запущенного процесса уже есть свой собственный уникальный идентификатор — он называется PID (Process ID) (например, у браузера PID может быть 4122).
Порт — это отдельная цифра, которую операционная система временно привязывает к этому PID, чтобы выводить программу в сеть.

В чем разница между PID и Портом?
PID нужен операционной системе, чтобы управлять программой внутри компьютера (выделять ей память, закрывать её, следить за нагрузкой на процессор). 
Сеть про PID ничего не знает.
Порт нужен операционной системе, чтобы связать сетевой кабель с этой программой.

## 🔹 Классификация портов (IANA)

| Диапазон | Название | Назначение |
|---|---|---|
| **0 – 1023** | Well-known (общеизвестные) | Зарезервированы для системных и широко известных служб (HTTP, SSH, DNS и др.). Требуют привилегий root для запуска. |
| **1024 – 49151** | Registered (зарегистрированные) | Выделяются IANA под конкретные приложения (MySQL, RDP, прокси и т.д.). Могут быть использованы непривилегированными пользователями. |
| **49152 – 65535** | Dynamic / Ephemeral (динамические) | Используются клиентскими приложениями как временные исходящие порты, либо для частных экспериментов. |

## 🔹 Ключевые порты и службы (выборочно)

| Порт | Служба | Протокол | Примечание |
|---|---|---|---|
| 21 | FTP | TCP | Передача файлов (часто без шифрования, атакуем перехватом) |
| 22 | SSH | TCP | Безопасное удалённое управление |
| 25 | SMTP | TCP | Отправка почты |
| 53 | DNS | UDP/TCP | Разрешение имён (может использоваться в туннелировании и DDoS-амплификации) |
| 80 | HTTP | TCP | Веб-трафик без шифрования |
| 443 | HTTPS | TCP | Веб-трафик с TLS |
| 3306 | MySQL | TCP | Системы управления БД (часто цель для атак на БД) |
| 3389 | RDP | TCP | Удалённый рабочий стол (цель для брутфорса и эксплуатации уязвимостей) |

## 🔹 Значение для информационной безопасности

### 1. Поверхность атаки
Каждый прослушиваемый порт увеличивает поверхность атаки. Открытый порт означает, что какая-то служба принимает соединения из сети. Если эта служба уязвима, скомпрометирована или избыточна — риск возрастает.

**Правило:** Держать открытыми только те порты, которые действительно нужны для функционирования системы, и минимизировать сетевые интерфейсы, на которых они слушают.

### 2. Разведка (Reconnaissance)
Первым шагом пентеста или атаки является сканирование портов. Злоумышленник определяет:
- какие порты открыты (`open`),
- какие отфильтрованы межсетевым экраном (`filtered`),
- какие закрыты (`closed`).

На основе открытых портов он идентифицирует сервисы и их версии (banner grabbing), а затем ищет известные уязвимости.

### 3. Основные векторы атак
- **Эксплуатация уязвимых служб** (например, старая версия SSH, SMB, веб-сервер без патча).
- **Брутфорс** учётных данных (SSH, RDP, FTP).
- **Туннелирование** вредоносного трафика через разрешённые порты (например, C&C через DNS или HTTPS), что затрудняет обнаружение.
- **Скрытие вредоносных сервисов** на нестандартных портах (SSH на 2222/TCP, веб-сервер на 8080) — это не панацея, но замедляет автоматизированное сканирование.

### 4. Мониторинг и аудит
- Регулярный аудит открытых портов — обязательная гигиена системы.
- Любое неожиданное появление нового слушающего порта — сигнал о возможной компрометации.
- Службы, которые должны слушать только локально (`127.0.0.1`), не должны быть доступны извне.

## 🔹 Инструменты и практика (шпаргалка)

| Действие | Команда | Что даёт |
|---|---|---|
| Список слушающих портов (TCP/UDP) | `ss -tuln` | Показывает порты в состоянии LISTEN, без разрешения имён служб |
| Показать процессы, занявшие порты | `ss -tulnp` (требует root) | Видно, какой процесс открыл порт |
| Альтернативный просмотр | `netstat -tulnp` | Устаревший, но ещё часто используется |
| Сканирование портов целевого хоста | `nmap -sS -p- <IP>` | Быстрое SYN-сканирование всех 65535 портов |
| Сканирование с определением версий | `nmap -sV <IP>` | Определение служб и их версий |
| Фильтрация трафика по порту | `tcpdump -i eth0 port 443` | Просмотр пакетов на конкретном порту |
| Ограничение доступа через iptables | `iptables -A INPUT -p tcp --dport 3306 -j DROP` | Запрещает входящие соединения на MySQL извне |

**Лучшая практика:** настроить межсетевой экран по принципу «запрещено всё, что не разрешено явно», а для внешнего сканирования периметра использовать сторонние сервисы (например, Shodan) для проверки того, что видно снаружи.

## 🔹 Как отвечать на собеседовании

**Кратко**: «Порт — это числовой идентификатор службы на транспортном уровне. Я регулярно проверяю открытые порты командой `ss -tulnp` и осознаю, что каждый лишний порт увеличивает поверхность атаки. При пентесте всегда начинаю с порт-сканирования через `nmap` и анализирую, какие службы нельзя оставлять открытыми».

**Развёрнуто**: Добавить про классификацию диапазонов, состояния портов (open, closed, filtered), необходимость закрывать неиспользуемые службы или ограничивать их по IP, а также про опасность сервисов на нестандартных портах и методы обнаружения скрытых туннелей.

## 🔗 Связи

- [[ss]] — аудит открытых портов и привязка к процессам.
- [[iptables]] — фильтрация трафика по портам, настройка политик.
- [[nmap]] — сканирование портов, определение версий, скрипты NSE.
- [[tcpdump]] — захват трафика на определённом порту для анализа.
- [[netstat]] — устаревшая, но всё ещё встречающаяся утилита для просмотра портов.

## ❓ Самопроверка

1. **Как быстро посмотреть все слушающие TCP и UDP порты на Linux?** 👉 `ss -tuln`
2. **Какой порт используется для защищённого веб-трафика?** 👉 `443/TCP` (HTTPS)
3. **Что означает состояние порта `FILTERED` при сканировании nmap?** 👉 Запрос не достиг порта или ответ не получен — скорее всего, трафик блокируется межсетевым экраном.
4. **Почему не стоит полностью полагаться на смену стандартного порта (например, SSH на 2222) для защиты?** 👉 Сканирование всех портов легко автоматизируется, и злоумышленник всё равно обнаружит SSH; защиту обеспечивает только строгая аутентификация и файрвол.
