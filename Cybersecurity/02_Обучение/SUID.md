# 🎯 SUID (Set User ID) — запуск файла от имени владельца

> [!abstract] Суть одной фразой
> SUID (Set User ID) — это специальный бит прав доступа, который заставляет исполняемый файл запускаться **от имени владельца файла**, а не от имени того, кто его запустил. В выводе `ls -la` обозначается буквой `s` в позиции выполнения для владельца (`-rwsr-xr-x`).

Для специалиста по ИБ SUID-файлы — это одновременно и полезный механизм, и потенциальный вектор эскалации привилегий, если бит установлен на уязвимой программе.

---

## 📌 Как это работает

1.  Обычный исполняемый файл (`-rwxr-xr-x`) запускается с правами пользователя, который его запустил.
2.  SUID-файл (`-rwsr-xr-x`) запускается с правами **владельца файла**. Если владелец — `root`, программа временно получает привилегии `root`.

Классический пример — команда `passwd`. Она должна изменять файл `/etc/shadow`, доступный только `root`. Благодаря SUID-биту `passwd` запускается от имени `root`, даже если её вызвал обычный пользователь.

## 🔢 Как задать и найти SUID-файлы

-   **Установить SUID-бит:** `chmod u+s file`
-   **Убрать SUID-бит:** `chmod u-s file`
-   **Числовой формат:** `chmod 4755 file` — 4 в начале означает SUID-бит.
-   **Найти все SUID-файлы в системе:** `find / -type f -perm -4000`

## 🕵️ Значимость для специалиста по ИБ

-   Я всегда проверяю список SUID-файлов при аудите. Нестандартный SUID-файл (`/tmp/backdoor`, `~/suspicious`) — красный флаг: возможно, злоумышленник создал лазейку для эскалации привилегий.
-   Я понимаю, что `-perm -4000` ищет по маске (наличие бита), а `-perm 4755` — точное совпадение.

## 💬 Ответ на собеседовании (кратко)

> «SUID-бит заставляет программу выполняться от имени её владельца, а не запускающего пользователя. Нужен, например, для `passwd`. Аудитор ищет подозрительные SUID-файлы командой `find / -type f -perm -4000`».
