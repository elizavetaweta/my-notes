# 📜 Протокол 

> [!abstract] Суть одной фразой
> Протокол — это **набор правил** обмена данными между устройствами. Для специалиста по ИБ знание протоколов — это умение читать трафик, выявлять аномалии и настраивать фильтрацию.

---

## 📌 Основные протоколы

- **TCP (Transmission Control Protocol)** — надёжный протокол с подтверждением доставки, контролем порядка и целостности. Используется в HTTP, SSH, FTP, SMTP.
- **UDP (User Datagram Protocol)** — быстрый протокол без гарантий доставки и без соединения. Применяется в DNS, VoIP, стриминге, онлайн-играх.
- **ICMP (Internet Control Message Protocol)** — служебные сообщения (проверка доступности `ping`, уведомления об ошибках, трассировка маршрута).
- **HTTP/HTTPS** — протоколы передачи гипертекста; HTTPS добавляет шифрование через TLS.
- **DNS (Domain Name System)** — преобразование доменных имён в IP-адреса (и обратно).
- **ARP (Address Resolution Protocol)** — связывание IP-адреса с MAC-адресом в локальной сети.

## 🧱 Классификация протоколов по уровням OSI

Протоколы работают на разных уровнях [[Модель OSI  (Open Systems Interconnection)|модели OSI]], и от этого зависит их роль:

| Уровень OSI | Тип протокола | Примеры | Задача |
|---|---|---|---|
| **L2 (Канальный)** | Протоколы локальной сети | [[ARP (Address Resolution Protocol)]], Ethernet | Передача кадров и связывание IP с MAC |
| **L3 (Сетевой)** | Протоколы маршрутизации и адресации | [[IP-адрес\|IP]], [[ICMP (Internet Control Message Protocol)]], [[IPsec]] | Доставка пакетов между сетями |
| **L4 (Транспортный)** | Транспортные протоколы | [[Протоколы транспортного уровня TCP и UDP\|TCP, UDP]] | Доставка данных приложениям (с гарантией или без) |
| **L7 (Прикладной)** | Прикладные протоколы | [[HTTP, HTTPS, HTTP 2, HTTP 3\|HTTP/HTTPS]], [[DNS (Domain Name System)]], [[FTP]], [[SSH]], [[SMTP]] | Предоставление услуг пользователю |
## 📦 Протоколы и единицы данных (PDU)

Каждый уровень оперирует своей единицей данных:
- **L2 (Канальный):** [[Кадр (Frame)|Кадр]] — оборачивает пакет, добавляя MAC-адреса.
- **L3 (Сетевой):** [[Пакет (сетевой)|Пакет]] — содержит IP-заголовок и данные.
- **L4 (Транспортный):** Сегмент (TCP) или датаграмма (UDP) — содержит порты и флаги.

Протоколы определяют, как формировать и обрабатывать эти единицы. Пакет — это «конверт», который создаётся по правилам протокола IP.

## 🕵️ Значимость для информационной безопасности

### 🔬 Анализ трафика
Умение видеть трафик на уровне протоколов – ключевой навык.  
Пример с **tcpdump**:  
`tcpdump -i eth0 tcp` — захват только TCP-пакетов.  
`tcpdump -i eth0 udp port 53` — перехват DNS-запросов.  

Пояснение флагов:  
- `-i` (**i**nterface) — сетевой интерфейс (например, `eth0`).  
- `tcp`, `udp` — фильтрация по протоколу.  
- `port 53` — фильтрация по номеру порта (DNS).

### ⚔️ Типичные атаки, использующие особенности протоколов
- **ARP-spoofing** — подмена MAC-адреса для перехвата трафика в локальной сети.
- **DNS-spoofing / cache poisoning** — подмена ответа DNS-сервера для перенаправления жертвы на ложный ресурс.
- **SYN-flood (TCP)** — заполнение очереди полуоткрытых соединений; выявляется по аномально большому числу пакетов с флагом SYN без завершения рукопожатия.
- **UDP amplification / flood** — атака усилением (например, через DNS/NTP) за счёт различия размеров запроса и ответа.
- **ICMP redirect / flood** — злоупотребление служебными сообщениями для обхода маршрутизации или исчерпания ресурсов.

### 🛡️ Фильтрация по протоколу
Межсетевые экраны (`iptables`, `nftables`) оперируют протоколами.  
Пример правила **iptables**:  
`iptables -A INPUT -p tcp --dport 22 -j ACCEPT`  

Где:  
- `-A INPUT` — добавить правило в цепочку INPUT.  
- `-p` (**p**rotocol) — указать протокол (tcp, udp, icmp…).  
- `--dport 22` — порт назначения.  
- `-j ACCEPT` — действие.

### 🧰 Просмотр открытых портов и протоколов
Утилита **ss** показывает, какие протоколы используют открытые сокеты.  
`ss -tuln` — TCP и UDP слушающие порты в числовом виде.  

Расшифровка:  
- `-t` (**t**cp) — показать TCP-сокеты.  
- `-u` (**u**dp) — показать UDP-сокеты.  
- `-l` (**l**istening) — только слушающие (открытые) порты.  
- `-n` (**n**umeric) — не преобразовывать IP и порты в имена (ускоряет вывод).

## ❓ Самопроверка

1. **Чем TCP отличается от UDP?**  
   👉 TCP устанавливает соединение и гарантирует доставку с сохранением порядка; UDP работает без соединения, не гарантирует доставку, но быстрее.
2. **Какой протокол использует `ping`?**  
   👉 ICMP (эхо-запрос и эхо-ответ).
3. **Как быстро проверить, какие TCP-порты слушает машина?**  
   👉 `ss -tln` или `netstat -tln`.
4. **Как захватить только входящий HTTP-трафик tcpdump?**  
   👉 `tcpdump -i eth0 tcp port 80`.
