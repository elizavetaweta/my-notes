# 📡 ping — проверка доступности хоста

> [!abstract] Суть одной фразой
> `ping` — это утилита для проверки доступности удалённого хоста и измерения времени прохождения пакетов туда и обратно (RTT, Round-Trip Time). Она отправляет ICMP Echo Request и ждёт ICMP Echo Reply. Для специалиста по ИБ это первый инструмент диагностики: «сервер жив?», «есть ли сеть?», «какая задержка?».

`ping` работает на сетевом уровне (L3 модели [[Модель OSI  (Open Systems Interconnection)|OSI]]) поверх протокола [[ICMP (Internet Control Message Protocol)]].

---

## 📌 Базовое использование

> ping 8.8.8.8
> ping google.com

- `8.8.8.8` — публичный DNS-сервер Google, стандартная цель для проверки интернета.
- `google.com` — проверка доступности домена (попутно проверяется работа [[DNS (Domain Name System)]]).

По умолчанию `ping` отправляет пакеты бесконечно. Остановить — `Ctrl + C`.

---

## 🔑 Ключевые опции

- `-c N` (**c**ount) — отправить ровно N пакетов и завершиться.  
  > ping -c 4 8.8.8.8
- `-i N` (**i**nterval) — интервал между пакетами в секундах (по умолчанию 1).  
  > ping -i 0.5 8.8.8.8
- `-W N` (**W**ait) — таймаут ожидания ответа в секундах.  
  > ping -W 2 -c 3 8.8.8.8
- `-4` / `-6` — принудительно использовать IPv4 или IPv6.
- `-f` (**f**lood) — «лавинная» отправка пакетов (требует root). Используется для стресс-тестов, но может рассматриваться как DoS-атака.

> [!danger] Осторожно с `ping -f`
> Лавинная отправка ICMP-запросов может перегрузить сеть или целевую систему. Никогда не применяй её к чужим хостам без письменного разрешения.

## 🔍 Как читать вывод ping

> 64 bytes from 8.8.8.8: icmp_seq=1 ttl=118 time=12.3 ms

- **`64 bytes`** — размер ответа в байтах. Стандартный, не важен для диагностики.
- **`icmp_seq=1`** — порядковый номер пакета. Помогает заметить потерю: если номера идут не подряд (1, 3, 4), значит, какой-то пакет не дошёл.
- **`ttl=118`** — оставшееся «время жизни» пакета (количество возможных прыжков). Чем ближе к нулю, тем дальше сервер. Например, при стартовом TTL 128 значение 118 означает, что между вами около 10 маршрутизаторов.
- **`time=12.3 ms`** — задержка туда-обратно (RTT). Основной показатель скорости канала: <1 мс — локальная сеть, 5–20 мс — город, 100+ мс — другой континент.

**Итоговая статистика** (после завершения) показывает процент потерянных пакетов и минимальное/среднее/максимальное время. Потери сигнализируют о проблемах, а большой разброс (max сильно выше min) — о нестабильности канала.

## 🕵️ Сценарии для ИБ

- **Проверка доступности:** `ping -c 4 192.168.1.1` — убедиться, что шлюз жив.
- **Обнаружение блокировки ICMP:** если `ping` не получает ответов, но хост доступен (например, открыт порт 443), значит, ICMP фильтруется файрволом.
- **ICMP Flood (DoS):** злоумышленник отправляет огромное количество ICMP-запросов, истощая канал жертвы. Мониторинг объёма ICMP-трафика позволяет обнаружить такую атаку.
