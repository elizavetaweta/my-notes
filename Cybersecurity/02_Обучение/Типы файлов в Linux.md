# 📁 Типы файлов в Linux

> [!abstract] Суть одной фразой
> В [[Linux]] **«всё есть файл»** — но файлы бывают разных типов. Тип файла обозначается **первым символом** в выводе `ls -la` и определяет, как система взаимодействует с этим объектом: читает как данные, исполняет, передаёт через него информацию или обращается к устройству.

Для специалиста по ИБ знание типов файлов помогает при аудите системы: ты сразу понимаешь, что перед тобой — обычный конфиг, ссылка, устройство или именованный канал, который может использоваться для межпроцессного взаимодействия.

---

## 📌 Все типы файлов (первый символ в `ls -la`)

| Символ | Тип файла             | Название (англ.)  | Суть                                                    |
| ------ | --------------------- | ----------------- | ------------------------------------------------------- |
| `-`    | Обычный файл          | Regular file      | Текст, бинарник, скрипт, лог, ключ                      |
| `d`    | Каталог               | Directory         | Папка, содержащая имена других файлов                   |
| `l`    | Символическая ссылка  | Symbolic link     | Указатель на другой файл или папку                      |
| `b`    | Блочное устройство    | Block device      | Доступ к данным блоками (жёсткий диск, SSD)             |
| `c`    | Символьное устройство | Character device  | Поточный доступ к данным (терминал, клавиатура, мышь)   |
| `s`    | Сокет                 | Socket            | Межпроцессное взаимодействие (IPC), в т.ч. по сети      |
| `p`    | Именованный канал     | Named pipe (FIFO) | Передача данных между процессами через файловую систему |

---

## 🔍 Подробнее о каждом типе

### `-` — Обычный файл (Regular file)

Самый частый тип. Содержит данные: текст, исполняемый код, изображения, архивы. Внутри может быть что угодно — от пароля до вредоносного скрипта.

> -rw-r--r-- 1 root root 1234 Mar 15 10:30 /etc/passwd

### `d` — Каталог (Directory)

Файл-справочник, который хранит список имён и соответствующих им номеров [[inode]]. По сути, это «оглавление» файловой системы.

> drwxr-xr-x 2 root root 4096 Mar 15 10:30 /etc/ssh/

### `l` — Символическая ссылка (Symbolic link)

Отдельный файл, который хранит **путь** к целевому объекту. В выводе `ls -la` показывает стрелку `->`.

> lrwxrwxrwx 1 root root 7 Mar 15 10:30 /bin/sh -> /bin/bash

Подробнее — в заметке [[Символические и жёсткие ссылки]].

### `b` — Блочное устройство (Block device)

Представляет оборудование, которое читается и пишется **блоками** (например, 512 байт). Это жёсткие диски, SSD, разделы. Через файл устройства система обращается к «железу».

> brw-rw---- 1 root disk 8, 0 Mar 15 10:30 /dev/sda

Цифры `8, 0` — это major и minor номера устройства (драйвер + конкретное устройство). Для специалиста по ИБ: здесь живут зашифрованные тома ([[LUKS]], [[VeraCrypt]]) и именно эти файлы проверяют на наличие скрытых разделов.

### `c` — Символьное устройство (Character device)

Похоже на блочное, но обмен данными идёт **потоком байтов** (посимвольно). Это терминалы (`/dev/tty`), клавиатура, мышь, генераторы случайных чисел.

> crw-rw-rw- 1 root tty 5, 0 Mar 15 10:30 /dev/tty

Особый интерес для ИБ представляет `/dev/urandom` — генератор случайных чисел, который используется для создания криптографических ключей.

### `s` — Сокет (Socket)

Файл, через который процессы обмениваются данными. В отличие от TCP-сокетов, которые работают по сети, Unix Domain Socket существует как файл в файловой системе.

> srw-rw-rw- 1 root root 0 Mar 15 10:30 /var/run/docker.sock

Для ИБ важно: сокет Docker — мощный вектор атаки. Если у злоумышленника есть доступ к этому файлу, он может управлять контейнерами от имени root.

### `p` — Именованный канал (Named pipe, FIFO)

Позволяет двум разным процессам обмениваться данными по принципу «первый вошёл — первый вышел» (First In, First Out). Данные не хранятся на диске — только передаются.

> prw-r--r-- 1 root root 0 Mar 15 10:30 /tmp/my_pipe

Злоумышленник может создать канал для перехвата данных, передаваемых между легитимными процессами, или для скрытой передачи украденной информации.

## 🧠 Значимость для меня как специалиста по ИБ

- Я понимаю, что первый символ в `ls -la` сразу говорит о природе объекта, и не путаю блочное устройство с обычным файлом.
- При аудите я обращаю внимание на сокеты (`s`) в `/var/run` и `/tmp` — особенно `docker.sock`, доступ к которому может дать злоумышленнику контроль над контейнерами.
- Я знаю, что именованные каналы (`p`) могут использоваться для перехвата данных, и проверяю нестандартные FIFO в `/tmp` и домашних папках.
- Я помню, что `/dev/urandom` (`c`) — критичный для криптографии источник случайности, и его компрометация ставит под удар всю систему шифрования.

## 💬 Ответ на собеседовании (кратко)

> «В Linux тип файла определяется первым символом в `ls -la`: `-` — обычный файл, `d` — каталог, `l` — символическая ссылка, `b` — блочное устройство (диски), `c` — символьное устройство (терминалы, /dev/urandom), `s` — сокет (IPC), `p` — именованный канал (FIFO). Каждый тип по-своему важен при аудите: сокеты могут дать контроль над Docker, каналы — использоваться для перехвата данных, а блочные устройства — скрывать зашифрованные тома».

## ❓ Самопроверка

1. **Что означает символ `b` в начале строки `ls -la`?**
   👉 Блочное устройство (диск, раздел).
2. **Чем символьное устройство отличается от блочного?**
   👉 Символьное передаёт данные посимвольно (потоком), блочное — блоками фиксированного размера.
3. **Почему файл `/var/run/docker.sock` с типом `s` важен для безопасности?**
   👉 Это Unix-сокет Docker API. Доступ к нему позволяет управлять контейнерами, в том числе запускать их с привилегиями root.
4. **Может ли обычный пользователь создать именованный канал (`p`)?**
   👉 Да, командой `mkfifo`. Злоумышленник может использовать его для перехвата данных.
