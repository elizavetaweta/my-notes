# 📧 SMTP (Simple Mail Transfer Protocol)

> [!abstract] Суть одной фразой
> SMTP — это сетевой протокол прикладного уровня, предназначенный для **отправки** электронной почты от клиента к серверу и для ретрансляции писем между почтовыми серверами. Он не предназначен для получения или хранения писем конечным пользователем — для этого используются POP3 или IMAP.

Для специалиста по ИБ SMTP — это критичный для бизнеса сервис, который часто становится мишенью атак и каналом утечки данных. Неправильно сконфигурированный SMTP-сервер может использоваться для рассылки спама, фишинга и социальной инженерии.

---

## 📌 Как работает SMTP

SMTP работает по классической [[Клиент (Client)|клиент-серверной]] модели поверх протокола [[Протоколы транспортного уровня TCP и UDP|TCP]].

1.  Почтовый клиент (MUA, Mail User Agent) отправляет письмо на SMTP-сервер (MTA, Mail Transfer Agent), указанный в настройках.
2.  SMTP-сервер отправителя обрабатывает письмо и, если получатель находится в другом домене, выступает в роли **SMTP-ретранслятора** (relay) и передаёт письмо на сервер получателя.
3.  Сервер получателя сохраняет письмо в почтовый ящик (MDA, Mail Delivery Agent), откуда его забирает конечный пользователь по протоколам POP3 или IMAP.

Каждый SMTP-сеанс состоит из команд (`HELO`/`EHLO`, `MAIL FROM`, `RCPT TO`, `DATA`) и ответов сервера в виде трёхзначных кодов (например, `250 OK`, `550 Mailbox not found`).

## 🔑 Стандартные порты

| Порт | Протокол | Назначение |
|---|---|---|
| **25** | TCP | Исторически первый порт. Используется для ретрансляции почты между серверами (MTA-to-MTA). |
| **465** | TCP | SMTPS (SMTP over SSL). Шифрованное соединение, устаревший стандарт. |
| **587** | TCP | SMTP Submission. Современный стандарт для отправки писем от клиента на сервер с обязательной аутентификацией и шифрованием (STARTTLS). |

## ⚔️ Проблемы безопасности

- **Перехват трафика и учётных данных.** Без использования STARTTLS или SMTPS логины, пароли и содержимое писем передаются в открытом виде, что позволяет злоумышленнику перехватывать их с помощью атак «человек посередине» (MITM).
- **Подделка отправителя (Email Spoofing).** Поле `MAIL FROM` аутентификация не требуется, поэтому адрес отправителя может быть сфальсифицирован. Для защиты применяются механизмы **SPF** (проверка IP-адреса отправителя через DNS), **DKIM** (цифровая подпись письма) и **DMARC** (политика обработки писем, учитывающая SPF и DKIM).
- **Открытый ретранслятор (Open Relay).** Если сервер разрешает пересылку писем от любых отправителей любым получателям без аутентификации, им активно пользуются спамеры. Такой сервер быстро попадает в черные списки, что разрушает репутацию домена.
- **Раскрытие учётных записей (VRFY и EXPN).** Команды `VRFY` (проверить пользователя) и `EXPN` (раскрыть почтовый список) позволяют собрать список существующих почтовых ящиков для дальнейших атак. В боевых системах их необходимо отключать.
- **Уязвимости в реализации ПО.** Баги в почтовых серверах (Exim, Postfix, Sendmail и т.д.) периодически приводят к удалённому выполнению кода (RCE) или отказу в обслуживании (DoS).

> [!danger] SMTP в корпоративной сети
> Открытый 25 порт без шифрования и открытый ретранслятор — критические находки при аудите. Весь современный клиентский трафик должен направляться строго через порт 587 с обязательным STARTTLS.

## 🛡️ Практический аудит и команды для специалиста ИБ

### 1. Сканирование портов и служб
`nmap` с флагом `-p` (**p**ort) для указания целевых портов. Расширенное определение сервиса включается флагом `-sV` (**s**ervice **V**ersion).

```bash
nmap -p 25,465,587 -sV <target>
```

### 2. Проверка на открытый ретранслятор
Скрипт NSE `smtp-open-relay` автоматически тестирует, разрешена ли неавторизованная пересылка. Флаг `--script` указывает какой именно скрипт Nmap Scripting Engine запустить.

```bash
nmap --script smtp-open-relay -p 25 <target>
```

Ручной тест можно провести с помощью `netcat` (или `telnet`), отправляя команды `HELO`, `MAIL FROM`, `RCPT TO`. Если сервер принимает `RCPT TO` с доменом, отличным от его собственного, и не требует аутентификации — ретранслятор открыт.

```bash
nc -v <target> 25
HELO example.com
MAIL FROM:test@example.com
RCPT TO:relaytest@external-domain.com
QUIT
```

### 3. Сбор поддерживаемых команд (включая VRFY/EXPN)
Для быстрого перечисления всех доступных команд используйте NSE-скрипт `smtp-commands`. Он покажет, разрешены ли `VRFY` и `EXPN` — потенциальные источники утечки информации.

```bash
nmap --script smtp-commands -p 25 <target>
```

### 4. Проверка поддержки шифрования и валидности сертификата
С помощью `openssl s_client` с опциями: `-starttls smtp` для инициирования шифрования на порту 587, `-crlf` для корректной передачи команд, а `-connect` для указания хоста и порта.

```bash
openssl s_client -starttls smtp -connect <target>:587 -crlf
```

### 5. Анализ SPF, DKIM и DMARC записей
Для проверки политик защиты домена используются запросы TXT-записей DNS. Утилита `dig` с типом запроса `txt` и с кратким выводом (`+short`) возвращает только нужную информацию.

```bash
dig txt <domain> +short       # Вернёт все TXT-записи, включая SPF и DMARC
dig txt _dmarc.<domain> +short # Конкретно DMARC-запись
dig default._domainkey.<domain> txt # DKIM селектора "default"
```

## 🕵️ Значимость для специалиста по ИБ

- Я проверяю, закрыт ли порт 25/TCP на периметре для клиентского доступа и сконфигурирована ли ретрансляция только для авторизованных узлов.
- При расследовании фишинговых атак я анализирую заголовки письма (`Received`, `Return-Path`, `DKIM-Signature`, `Authentication-Results`), чтобы проследить путь сообщения и установить истинного отправителя.
- Я настраиваю SPF, DKIM и DMARC для защиты домена организации от подделки писем.
