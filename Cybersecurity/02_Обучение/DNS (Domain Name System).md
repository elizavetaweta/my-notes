# 🌍 DNS (Domain Name System)

> [!abstract] Суть одной фразой
> DNS — это система доменных имён, которая переводит понятные человеку адреса (`google.com`) в IP-адреса (`142.250.185.46`), понятные компьютерам. Для специалиста по ИБ DNS — это не просто «телефонная книга интернета», а вектор атак, инструмент обхода блокировок, источник разведданных (footprinting) и ценнейший источник улик при расследовании инцидентов.

---

## 📌 Как работает DNS (упрощённо)

1. Ты вводишь в браузере `example.com`.
2. Компьютер проверяет локальный кэш DNS и файл `hosts`. Если записи нет, отправляет запрос настроенному DNS-резолверу.
3. Резолвер рекурсивно (или итеративно) опрашивает корневые, TLD-серверы и авторитативный сервер домена, пока не получит IP-адрес.
4. DNS-сервер возвращает ответ, и браузер устанавливает соединение с полученным IP.

```mermaid
graph LR
    A[Клиент] -->|Запрос: Какой IP у example.com?| B[DNS-резолвер]
    B -->|Ответ: 93.184.216.34| A
    A -->|Устанавливает соединение| C[Web-сервер 93.184.216.34]
```

## 🔑 Ключевые типы DNS-записей

| Тип | Что хранит | Пример |
|---|---|---|
| **A** | IPv4-адрес домена | `example.com → 93.184.216.34` |
| **AAAA** | IPv6-адрес домена | `example.com → 2606:2800:220:1:248:1893:25c8:1946` |
| **CNAME** | Каноническое имя (алиас) | `www.example.com → example.com` |
| **MX** | Почтовый сервер домена | `example.com → mail.example.com` |
| **NS** | DNS-сервер, обслуживающий домен | `example.com → ns1.example.com` |
| **PTR** | Обратная запись (IP → домен) | `93.184.216.34 → example.com` |
| **SOA** | Начальная запись зоны (служебная) | `example.com → ns1.example.com. admin.example.com. 2024032401 ...` |
| **TXT** | Произвольные текстовые данные (SPF, DKIM, проверка владения) | `example.com → "v=spf1 include:_spf.google.com ~all"` |
| **SRV** | Указывает серверы для определённых служб (SIP, LDAP) | `_sip._tcp.example.com → 10 60 5060 sip.example.com.` |

## 🚨 DNS как вектор атак и угрозы

### 🎭 DNS Spoofing / Cache Poisoning
Злоумышленник подменяет ответ DNS-сервера (например, через поддельный ответ до получения легитимного) или отравляет кэш резолвера. Жертва направляется на фишинговый или вредоносный сайт, хотя вводит правильный домен.  
**Защита:** внедрение DNSSEC (цифровая подпись ответов), ограничение рекурсии, использование только доверенных резолверов.

### 🕳️ DNS Tunneling
Скрытая передача данных (команды C2, эксфильтрация) через DNS-запросы и ответы. Данные кодируются в теле записей (часто TXT, NULL) в поддоменах. Трафик часто проходит незамеченным через файрволы и DLP-системы.  
**Обнаружение:** анализ частоты, длины и энтропии DNS-запросов, мониторинг TXT-записей, статистические аномалии.

### 💣 DNS Amplification DDoS
Открытые DNS-резолверы используются как отражатели: злоумышленник отправляет небольшой запрос с поддельным IP жертвы, а сервер возвращает многократно увеличенный ответ.  
**Защита:** отключение открытой рекурсии, rate limiting, response rate limiting (RRL).

### 🤖 DGA (Domain Generation Algorithm)
Вредоносное ПО генерирует множество доменов для связи с C2. Знание схемы DGA помогает прогнозировать будущие домены и блокировать их.  
**Роль в ИБ:** пассивный DNS и машинное обучение применяются для выявления DGA-активности.

### 🔁 Другие угрозы
- **DNS Rebinding** — атака, позволяющая обойти Same-Origin Policy браузера через манипуляцию временем жизни (TTL) DNS-ответа.
- **Fast Flux DNS** — быстрая смена IP-адресов за доменом, затрудняющая блокировку фишинговых и вредоносных сайтов.
- **Dangling DNS / Subdomain Takeover** — захват поддоменов, указывающих на облачный сервис, который уже не принадлежит владельцу домена.

## 🛡️ Защита DNS

| Уровень защиты | Меры |
|---|---|
| **Целостность** | Внедрение DNSSEC для предотвращения подделки ответов |
| **Конфиденциальность** | Использование DNS over TLS (DoT) или DNS over HTTPS (DoH) для шифрования запросов |
| **Мониторинг** | Анализ DNS-трафика (Zeek, Suricata), ведение логов, детектирование аномалий |
| **Фильтрация** | DNS Response Policy Zones (RPZ), блокировка известных вредоносных доменов |
| **Усиление инфраструктуры** | Отключение открытой рекурсии, ограничение зонных передач (AXFR), сегментация DNS-серверов |

---

## 🕵️ DNS в расследованиях (DFIR)

- **Пассивный DNS:** позволяет определить, какие домены разрешал целевой резолвер, и найти связанные инфраструктуры.
- **Анализ логов:** по DNS-запросам можно восстановить временные метки атак, обнаружить связь с C2, выявить DGA‑паттерны.
- **Корреляция:** совмещение DNS с сетевыми логами даёт полную картину взаимодействия скомпрометированного хоста.

## 🔧 Инструменты

**Базовые консольные утилиты:**
```bash
dig example.com A             # запросить A-запись
dig -x 93.184.216.34          # обратный поиск (PTR)
nslookup example.com
host example.com
```
**Разведка и перебор поддоменов:**
- `dnsrecon` – автоматизированный сбор DNS-информации
- `dnsenum` – перебор поддоменов и WHOIS-запросы
- `sublist3r`, `massdns` – мощные инструменты для поиска субдоменов

**Захват и анализ трафика:**
- `tcpdump -i eth0 port 53` – захват DNS-пакетов
- `wireshark`, `zeek`, `suricata` – протокольный анализ и детектирование аномалий

**Пассивный DNS и OSINT:**
- VirusTotal, SecurityTrails, Shodan, Farsight DNSDB

## 🔗 Связи

- [[IP-адрес]] — то, во что DNS превращает домены.
- [[Протокол]] — DNS работает поверх UDP (порт 53), TCP используется для больших ответов и зонных передач (AXFR).
- [[tcpdump]] / [[Wireshark]] — захват и анализ DNS-трафика.
- [[Модель OSI]] — DNS работает на прикладном уровне (L7).
- [[DNSSEC]] — цифровая подпись для защиты целостности ответов.
- [[Пассивный DNS]] — база исторических данных о разрешении имён.
- [[WHOIS]] — информация о владельцах доменов и NS-серверах.

## ❓ Самопроверка

1. **Что делает A-запись?** 👉 Связывает домен с IPv4-адресом.
2. **Какой порт и протоколы использует DNS?** 👉 Порт 53; основной транспорт — UDP; TCP используется при превышении 512 байт (EDNS) и для зонных передач.
3. **Что такое DNS-spoofing?** 👉 Подмена ответа DNS-сервера (часто сrace-условиями) для перенаправления жертвы на фишинговый сайт.
4. **Что такое DNSSEC и от каких атак он защищает?** 👉 Расширение DNS с цифровой подписью ответов. Защищает от подделки (spoofing) и отравления кэша, но не шифрует трафик.
5. **Как можно обнаружить DNS-туннелирование?** 👉 По аномальной длине запросов, высокой энтропии имён, резкому росту TXT-запросов или частоты обращений к одному домену.
6. **Чем опасен открытый DNS-резолвер?** 👉 Может быть использован в amplification DDoS-атаках и для обмана кэша, а также раскрывает запросы любых клиентов, что нарушает корпоративную политику.
