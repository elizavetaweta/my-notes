
## ❓ Самопроверка

> [!question]- Что делают права 600, 644 и 755 в числовом виде?
> - `600` — только владелец может читать и писать (`rw-------`). Стандарт для SSH-ключей.
> - `644` — владелец читает и пишет, группа и остальные только читают (`rw-r--r--`). Для конфигов.
> - `755` — владелец может всё, группа и остальные — читать и выполнять (`rwxr-xr-x`). Для скриптов и папок.

600 (rw-------) - владелец может читать (4), изменять (2), не может выполнять (1), группа и остальные не могут читать, изменять, выполнять.
rw-------
644 (rw-r--r--) - владелец может читать (4), изменять (2), не может выполнять (1),  группа и остальные могут читать (4), не могут изменять (2), и выполнять (1).
755 (rwxr-xr-x) - владелец может читать (4), изменять (2) и выполнять (1), группа и остальные, могут читать (4), выполнять (1), не могут изменять (2). 

> [!question]- Как добавить право на выполнение только владельцу, не меняя остальные права?
> `chmod u+x script.sh`

Команда chmod
chmod u+x filename.txt

> [!question]- Почему `chmod 777` — это опасная команда?
> Она даёт полный доступ (чтение, запись, выполнение) **всем** пользователям системы. Если применить к файлам вроде `/etc/shadow` или закрытому ключу, любой сможет их прочитать или изменить — это катастрофа для безопасности.

Потому что она дает права на чтение, изменение и выполнение всем пользователям.

> [!question]- Как посмотреть все открытые TCP-порты на сервере?
> `ss -tln`

> [!question]- Как узнать, какой процесс слушает порт 443?
> `ss -tlnp sport = :443`

> [!question]- Как посмотреть все установленные соединения (без слушающих портов)?

> [!question]- Чем `ss` принципиально лучше устаревшего `netstat`?
> `ss` читает данные напрямую из ядра, работает быстрее и поддерживает более гибкую фильтрацию. `netstat` официально признан устаревшим.

## ❓ Самопроверка

> [!question]- Как посмотреть все текущие правила iptables?
> `iptables -L -n -v`

> [!question]- Как разрешить входящие соединения на порт 22 (SSH)?
> `iptables -A INPUT -p tcp --dport 22 -j ACCEPT`

> [!question]- Как запретить всё входящее и открыть только порты 80 и 443 (белый список)?
> ```bash
> iptables -P INPUT DROP
> iptables -A INPUT -p tcp --dport 80 -j ACCEPT
> iptables -A INPUT -p tcp --dport 443 -j ACCEPT
> iptables -A INPUT -m state --state ESTABLISHED,RELATED -j ACCEPT
> ```

> [!question]- Чем DROP отличается от REJECT?
> `DROP` молча отбрасывает пакет, отправитель не получает никакого ответа. `REJECT` возвращает отправителю ICMP-сообщение об ошибке. `DROP` лучше для безопасности (не выдаёт информацию о системе), но `REJECT` удобнее для диагностики.

## ❓ Самопроверка

> [!question]- Как отсортировать файл по числам (а не по алфавиту)?
> `sort -n файл`

> [!question]- Как отсортировать файл по убыванию?
> `sort -r файл`

> [!question]- Почему перед `uniq` всегда нужно выполнять `sort`?
> `uniq` считает повторы только среди **соседних** строк. `sort` группирует одинаковые строки вместе. Без `sort` `uniq` даст неверный результат.

## ❓ Самопроверка

> [!question]- Как вывести первый и третий столбцы из вывода `ps aux`?
> `ps aux | awk '{print $1, $3}'`

> [!question]- Как найти всех пользователей с UID ≥ 1000 в `/etc/passwd`?
> `awk -F ':' '$3 >= 1000 {print $1}' /etc/passwd`

> [!question]- Чем `awk` удобнее `cut` при работе с логами?
> `awk` автоматически схлопывает повторяющиеся пробелы в один разделитель, поэтому номера столбцов не «плывут». `cut` считает каждый пробел отдельным полем, что делает его ненадёжным для разбора логов с плавающим форматированием.
