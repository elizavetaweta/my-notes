# 📁 Файловая система (File System)

> [!abstract] Суть одной фразой
> Файловая система — это способ организации, хранения и управления данными на носителе информации. Она определяет, как файлы называются, где располагаются на диске, кто и как может к ним обращаться.

Для специалиста по ИБ файловая система — это не просто «место, где лежат файлы». Это источник улик при расследовании инцидентов, объект аудита прав доступа и среда, в которой работают механизмы защиты (шифрование, контроль целостности, журналирование).

---

## 📌 Зачем нужна файловая система

Без файловой системы данные на диске были бы просто сплошным потоком байтов. Вы не смогли бы найти нужный файл, определить его размер или понять, кому он принадлежит. Файловая система решает эти задачи:

- **Именование и иерархия:** файлы объединяются в каталоги (папки), образуя привычное дерево.
- **Метаданные:** для каждого файла хранится информация о владельце, правах доступа, времени создания/изменения/последнего доступа.
- **Управление пространством:** система знает, какие участки диска заняты, а какие свободны.
- **Надёжность:** современные файловые системы (ext4, XFS, NTFS) поддерживают журналирование — запись всех операций в специальный журнал перед их выполнением. Это позволяет восстановить целостность после внезапного сбоя питания.

---

## 🖥️ Основные типы файловых систем

| Файловая система | Где используется | Особенности, важные для ИБ |
|---|---|---|
| **ext4** | Linux (основная) | Поддержка прав доступа UNIX (rwx), журналирование, шифрование на уровне блочного устройства (LUKS) |
| **XFS** | Linux (серверы, большие объёмы) | Высокая производительность, журналирование, хорошая работа с большими файлами |
| **NTFS** | Windows | Разграничение доступа (ACL), шифрование (EFS), сжатие, альтернативные потоки данных (ADS — могут скрывать вредоносный код) |
| **FAT32 / exFAT** | Внешние носители, флешки | **Нет встроенного разграничения доступа** — любой, кто держит флешку в руках, может прочитать все файлы |
| **APFS** | macOS | Шифрование, снапшоты, эффективная работа с SSD |

> [!note] Почему это важно
> При аудите или расследовании ты определяешь тип файловой системы, чтобы понимать, какие механизмы защиты доступны и какие артефакты можно извлечь.

## 🔐 Права доступа — основа безопасности

Файловая система хранит для каждого файла и каталога три вида разрешений:

| Режим | Для файла | Для каталога |
|---|---|---|
| **r** (read) | Можно прочитать содержимое | Можно посмотреть список файлов |
| **w** (write) | Можно изменить содержимое | Можно создавать и удалять файлы |
| **x** (execute) | Можно запустить как программу | Можно войти в каталог |

Разрешения задаются для трёх категорий: **владельца**, **группы** и **всех остальных**.

> [!danger] Типичная ошибка
> Права `777` (всем можно всё) на файлах с паролями или закрытых ключах — это критическая уязвимость. При аудите я всегда проверяю права на критичные файлы: `/etc/shadow`, закрытые ключи SSH, конфигурации VPN.

## 🔢 Что означают цифры в правах доступа (777, 755, 644)

Права доступа в Linux можно записывать не только в символьном виде (`rwxr-xr-x`), но и в **восьмеричном (цифровом)**. Каждая цифра — это сумма трёх битов:

| Бит | Значение | Обозначение |
|---|---|---|
| **4** | Чтение | `r` (read) |
| **2** | Запись | `w` (write) |
| **1** | Выполнение | `x` (execute) |

Три цифры подряд задают права для **владельца (user)**, **группы (group)** и **всех остальных (others)**. Например:

| Цифровой код | Символьный код | Смысл |
|---|---|---|
| `7` = 4+2+1 | `rwx` | Можно читать, изменять и запускать |
| `5` = 4+0+1 | `r-x` | Можно читать и запускать, но **нельзя изменять** |
| `4` = 4+0+0 | `r--` | Только чтение |
| `0` = 0+0+0 | `---` | Ничего нельзя |

Таким образом, **`777`** = `rwxrwxrwx` — **полный доступ для всех**. Это катастрофа для любого критичного файла.

> [!example] Типичные безопасные значения
> - `644` (rw-r--r--) для обычных файлов: владелец редактирует, остальные только читают.
> - `755` (rwxr-xr-x) для скриптов и каталогов: владелец управляет, остальные могут выполнять и просматривать.
> - `600` (rw-------) для приватных ключей: только владелец читает и пишет.

## 🕵️ Что важно знать специалисту по ИБ

### 1. Метаданные и временные метки
Файловая система хранит **MAC-времена** (mtime, atime, ctime):
- **mtime** — время последнего изменения содержимого файла.
- **atime** — время последнего доступа (чтения).
- **ctime** — время последнего изменения метаданных (прав, владельца).

При расследовании инцидента эти метки помогают восстановить хронологию действий злоумышленника.

### 2. Удалённые файлы и восстановление
При удалении файла в большинстве файловых систем удаляется только запись о нём в таблице, а сами данные остаются на диске до момента перезаписи. Именно поэтому:
- Работают утилиты восстановления данных (TestDisk, PhotoRec).
- Требуется **безопасное удаление** (многократная перезапись случайными данными).

### 3. Slack space (файловый «слак»)
Поскольку файловая система выделяет место кластерами (блоками фиксированного размера), последний кластер почти всегда заполнен не полностью. Остаток кластера называется **slack space** и может содержать фрагменты старых файлов, которые были на этом месте ранее. Это ценный источник улик при криминалистическом анализе.

### 4. Альтернативные потоки NTFS (ADS)
В NTFS один файл может содержать несколько независимых потоков данных. Основной поток отображается как обычный файл, а дополнительные потоки **не видны** в стандартном проводнике Windows. Злоумышленники могут прятать вредоносный код в альтернативном потоке безобидного на вид файла.

## 🔗 Связи

- **[[Операционная система]]** — файловая система является её неотъемлемой частью.
- **[[Linux]]** — основная ОС, в которой ты работаешь с ext4/XFS.
- **[[VeraCrypt]]** — создаёт зашифрованный контейнер, внутри которого может быть любая файловая система.
- **[[Защита от НСД]]** — права доступа к файлам — один из базовых механизмов защиты.
- **[[Аудит ИБ]]** — проверка прав доступа и целостности файлов является частью аудита.
- **[[Триада КЦД]]** — файловая система обеспечивает целостность (журналирование) и доступность, а в связке с шифрованием — конфиденциальность.

## ❓ Самопроверка

1. **Что означают права `rwx` для файла?**
   👉 `r` — можно читать, `w` — можно изменять, `x` — можно выполнить как программу.

2. **Почему права `777` на закрытом ключе — это проблема?**
   👉 Потому что любой пользователь системы может прочитать и скопировать этот ключ, что полностью компрометирует защиту.

3. **Можно ли восстановить файл, удалённый из корзины?**
   👉 Да, во многих случаях можно, потому что файловая система удаляет только запись о файле, а сами данные остаются на диске до момента перезаписи.

4. **Что такое альтернативные потоки NTFS?**
   👉 Это скрытые дополнительные потоки данных у одного файла, невидимые в стандартном проводнике Windows. Могут использоваться для сокрытия вредоносного кода.
